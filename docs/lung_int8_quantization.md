# 肺分割模型的 INT8 静态量化验证

这是电脑上的真实量化卷积精度验证，不是 FPGA 推理，也不是 RTL 位精确仿真。
仅用于工程教学与算法演示，不作为临床诊断依据。

## 2026-10-11 实际结果

全部 18 个训练病例、3002 层校准完成，6 个验证病例、1120 层全部评价。
14 个 BN 已折叠，全部训练输入的最大 logits 绝对误差为 **0.000185013**，
通过预先设定的 rtol/atol 均 0.0002 检查。
全部 15 个卷积已成为真实 CPU 量化卷积，模型保存重载后输出逐值一致。

平均病例 Dice 下降 **0.000164068**，小区逐切片 Dice 下降 **0.000381071**；
通过本轮预先声明的 Dice 工程筛查阈值。六病例合计 25371 个像素输出不同，
约占全部输出像素 0.008641%；这不是临床误诊率，也不是相对人工标注的错误率。
空层误分像素减少不代表模型获得了新的分割能力，原小区漏分问题仍然存在。

本轮 BN 对拍关闭 CUDA TF32，浮点基线重新运行；与历史浮点报告的微小差异
来自执行数值路径，不是改了权重或原标签。比较以本轮同协议两种结果为准。
这仍是开发验证，不是 INT8 的独立外部测试。

权重本体从每元素 4 字节变成 1 字节，不能推导整机资源/速度变成四分之一。

额外状态，不能把两个不同内容的文件体积直接当权重压缩率。

后续必须明确 DDR/BRAM 分层调度而不是假定整个 U-Net 能无代价纯流式串联。

48 项完整工程测试通过，含真实 CUDA→CPU 观察器转换回归。
旧浮点权重和开发清单 SHA256 保持不变；原测试数据未用于本轮校准或评价。

## 本轮范围

冻结原 2D 第 12 轮 `early_stop_run/best.pt`，不训练、不修改旧权重，不使用
预留测试数据或正在下载的 COVID 数据。校准使用原 18 个训练病例的全部
3002 层归一化 CT，不读人工标签。评价使用原 6 个验证病例的全部 1120 层。

流程：复制模型 → 折叠 14 个卷积后的 BatchNorm → 对全部训练输入检查
折叠前后 logits 一致性 → 校准激活范围 → 转换 15 个真实量化卷积 →
保存/重载整数模型一致性检查 → 验证集与浮点模型、原始尺寸人工掩膜比较。
没有根据验证分数选择不同量化策略、层精度或阈值。

## 精度与计算边界

- 使用现有 PyTorch 2.8.0 的 CPU `x86` 静态量化后端，无新增依赖。
  该版本的 eager 量化接口有弃用提示，未来升级需迁移并重新验证；本轮不升级环境。
- 卷积权重：有符号 INT8，每个输出通道单独缩放。
- 特征图：无符号 UINT8 仿射量化，包含 scale 和 zero point。
  默认 HistogramObserver 校准配置采用 reduce_range；它与实际 UINT8 存储范围
  是不同概念，不能宣称所有层使用同一种有符号 INT8 网格。
- MaxPool、最近邻放大和 skip concat 保持量化数据通路，concat 进行量化网格重缩放。
  自动检查全部 15 个卷积已经转换，无浮点卷积残留。
- 模型输出 logits 解量化后，Sigmoid、恢复原始尺寸的概率双线性插值及
  `>=0.5` 判定沿用浮点流程。输入 HU 归一化/缩放与显示也在核心外。
  没有声称整条医学图像处理流水线全为整数。
- 有非零 zero point 时，整数 MAC 应按中心化数据或偏置补偿实现；
  不能直接把 UINT8 重解释为 INT8，中心化激活可能需要 9 位。
- 导出实际 INT8 权重、逐通道 scale/zero point、原 FP32 bias，以及采用
  round-to-even 约定提出的 INT32 bias。逐层给出保守 INT32 累加上界检查。
  **提出的 bias 约定不等于 CPU 后端内部实现已经位精确匹配**；RTL 的偏置、
  舍入、饱和、重缩放乘数/移位仍需设计和对拍。

实现依据：[PyTorch 2.8 静态量化说明](https://docs.pytorch.org/docs/2.8/quantization.html)、
[卷积与 BatchNorm 折叠接口](https://docs.pytorch.org/docs/2.8/generated/torch.nn.utils.fuse_conv_bn_eval.html)。

## 运行和产物

在项目根目录电脑 PowerShell 执行，不在板卡 Jupyter 执行：

```powershell
.\.venv-lung\Scripts\python.exe python/lung_quantize.py --dataset data/lung_learning_20261009/dataset.json --checkpoint data/lung_training_20261011/early_stop_run/best.pt --outdir data/lung_training_20261011/int8_ptq_validation_v2 --device cuda
```

`--device cuda` 用于浮点折叠检查和校准；真正 INT8 卷积运行在 CPU。
GPU 浮点与 CPU 整数的时间不是同硬件对比，不能推导加速比、板端 FPS 或功耗。
复跑必须指定新的空目录，不能覆盖已完成报告。

输出包括：

- `protocol.json`：源权重/代码/开发清单哈希、量化配置、固定阈值和数据范围。
- `calibration.json`：实际训练病例/切片、输入缓存哈希、BN 折叠最大误差。
- `int8_model.pt`：量化模型 state_dict，可由 `restore_quantized()` 恢复。
- `int8_core_parameters.npz`：实际整数权重与量化参数，以及标为 proposed 的 INT32 bias。
- `core_manifest.json`：15 层的尺寸、MAC、权重字节、scale/zero point、累加上界、skip 缓存。
- `evaluation.json`、`case_metrics.csv`：原始尺寸人工掩膜上的浮点/量化对比。
- 每验证病例的两种预测和 `quantization_slice_*.png`：青色人工、黄色浮点、绿色量化；
  红色多分、蓝色漏分、灰色正确，包含困难层而不是只选好的层。

程序运行前写入工程筛查阈值：平均病例 Dice 下降不超过 0.005，小区逐切片
Dice 下降不超过 0.03。它们不是医学或临床验收标准；空层误分同时报告，
即使 Dice 检查通过也不能忽略误分或宣称临床安全。

第一次 `int8_ptq_validation/` 在 GPU→CPU 转换时失败，没有评价真实验证病例。
已保留 `failure.json` 和校准记录。问题是 PyTorch observer 工厂的闭包引用原 GPU
模块，deepcopy 后 `.cpu()` 不会改变闭包引用；修复重新绑定 CPU 工厂但保留
已校准激活观察器，并增加真实 CUDA→CPU 回归检查。重跑的量化方案保持不变。
