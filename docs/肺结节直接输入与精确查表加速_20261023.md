# 肺结节：直接输入与精确查表分项加速

## 真实瓶颈与计时边界

用户回传 `data/nodule_canvas_speed_01` 已通过独立验收。当前统一计算版 PL 完整平面为 1778.761 ms，同算法 ARM 为 1692.721 ms，PL 多耗时 5.08%。PL 从上一版 2240.628 ms 降低 20.61%，这不是相对 ARM 的加速比。

三个正式样本的平均分解：

| 项目 | 时间 |
|---|---:|
| 在线五层上下文采样 | 819.470 ms |
| NumPy 查表量化及 stride-2 展开为 CHW | 123.466 ms |
| CHW 转换 HWC8、复制至 CMA 及输入同步 | 286.508 ms |
| 配置寄存器 | 4.812 ms |
| C++ 权重装载 | 6.109 ms |
| 启动、等待及完成统计 | 226.214 ms |
| 保护区/设备结果同步 | 4.327 ms |
| 读取并拆出检测头 | 14.906 ms |
| 候选解码和平面合并 | 269.068 ms |

硬件活动计数折算为 223.105 ms，包含 DDR 等待、写应答及所有卷积/张量算子，不是纯 MAC 时间；该计数已包含于“启动、等待及完成统计”之内，不能重复相加。剩余分配、反量化和主机操作归入总时间。

原 ARM 网络调用为 454.614 ms。不能把 ARM 的完整路径与 PL 的硬件计数直接相除并称为端到端加速，但这些记录明确表明 PL 输入搬运存在很大的优化空间。

## 这次的两项独立改动

### 1. C++ 直接准备输入

新增支持 128..1024、8 倍数矩形的本地 C++ 打包器：将 INT16 HU 查表量化、stride-2 邻域展开和 HWC8 排布一次写入输入 CMA。HWC8 按像素连续写入，避免 45 次跨步写目标缓存行。ARM 对照也使用同一新打包器产生 CHW，防止只给 PL 优化共享处理而夸大平台差异。

量化表仍由原 FP64 公式生成；输入边界、三个填充通道、OIHW 展开顺序和数值保持不变。没有降低分辨率、跳过检测平面、调高候选阈值或删去保护检查。

`DirectCanvasPL` 保留原有 15 条命令、全部输出计数/完成序号检查、12 个分配的保护区、输出同步，以及超时保留仍可能被 AXI 使用的内存。中间特征由 PL 生成，ARM 不做卷积。

### 2. 迁移已经路由验收的精确拼接查表 bit

当前结节的 flow-v1 bit 为 `20e22607b5f58a12b63ac011c5c814f996b052823a0b7f7c2bd4ba340c14bd07`。

新独立包复用肺分割已验收的 exact-LUT bit `54f54656e405eb4cee0ce073d476665110ee49ef6f200ccdaf6edc814a85cafc`。逐文件比较，差异只有张量引擎；卷积、参数及 MMIO ABI 保持兼容。已核对路由 source、bit/HWH 身份、100 MHz、setup/hold 和原有验证证据。不重新生成 bit，也不覆盖已有父包。

查表是每条拼接命令根据当次原 Q31/RNE 参数生成两个分支各 256 项的完整映射，不是近似量化。它改善张量重缩放，不能把该 bit 的肺分割速度直接当作结节速度。

## 精度验证与边界

- 7 项原生打包/调度检查：覆盖全部 65536 种 INT16 HU、矩形和极端值、只读带跨度输入、尾通道和越界保护、真实 448×448 所有节点、重复运行的缓存所有权、完整候选、DMA 保护与超时保留，以及动态库不遮蔽 Python 导入。
- 新 LUT 真实 RTL 穷举：原极端舍入测试加当前 `cat1`/`cat0` 参数，共 5120 项编码，8 条 lane 全部核对。
- 新 LUT 真实 448×448 全网络 RTL：复用原先已验收的初始输入和全部 11 节点参考输出。只注入初始输入，后续消费前面实际 RTL 写入 DDR 的结果。检查保护区、尾通道、AXI 阻塞和最终 B 应答。以交付包的证据记录为准。
- 上板时先检查新 LUT bit 对 4 个真实原始 patch 的全部节点，再比较各方案完整 5×224×224 检测头和最终候选；任何不一致即停止，测速记录作废。

原 75 例校准回归仍是已交付基线的结果：88/94、93.62%，322/75 = 4.2933 误报/病例。本轮没有重训或重新选择阈值，也没有把同一批 CT 重跑并称为新的独立测试；通过输入字节、精确算子和完整网络逐值验证来检查执行优化的等价性。新路径的物理板输出仍须通过脚本现场核验。

## 五组对照

| 名称 | 输入打包 | 网络执行 |
|---|---|---|
| `canvas_ARM` | 原 NumPy CHW | ARM 双核原生 INT8 |
| `native_ARM` | 新 C++ CHW | 同一 ARM 内核 |
| `canvas_PL` | 原 NumPy CHW→HWC8 | 原 flow bit |
| `direct_PL` | 新 C++ 直接 HWC8 CMA | 原 flow bit |
| `direct_LUT_PL` | 同一新 C++ 直接输入 | 已验收 exact-LUT bit |

各次仍在线执行相同的 SciPy 采样、网络和候选解码。主计时不包含模型构造、bit 切换、仅用于核对的额外比较、先前肺分割、数据传输和整卷跨层评分。

`direct_input` 表示同 bit 下输入路径的收益；`lut_only` 表示同输入路径下更换精确查表硬件的收益；`same_native_arm_vs_lut_pl` 才是新方案对齐输入实现后的 ARM/PL 对比。

采样在本轮保持一致，仍约占原总时间 46%。本包用于单独测清两项收益，不承诺总延迟按硬件周期等比例缩短。后续采样优化须逐像素验证插值、Z 混合和最近偶数舍入，不能直接改为最近邻或减少上下文层数。

已发现的后续方向是跨检测层复用重采样后的原生 CT 平面：目前 `SharedPlaneSampler` 只在单个检测平面内部共享，相邻检测平面再次需要同一原生层时会重新插值。可探索固定全局网格、受内存上限约束的平面缓存及按原坐标裁取。需要逐像素核对，分别测首次准备、持续吞吐和整病例总时间，不能预先计算好输入后把准备时间漏掉。本轮尚未实施这项缓存。
