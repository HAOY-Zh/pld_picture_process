## 硬件改动与精度约束

唯一有功能变化的源文件是包中 `rtl/lung_conv8_window.v`。它在原窗口生成器与常驻权重 MAC 输入之间加入 64×94 bit 的有限 FIFO：数据、通道 keep、first/last、像素坐标、帧尾及错误标记一起排队。RAM 不复位，复位清空指针和有效项数量，防止旧帧残留被当成新数据。

窗口端满队列时反压；计算端实际消费时才更新输出坐标和像素错误信息。FIFO ready 不依赖计算端的组合 ready，从而切开窗口/缓存到权重读取的长组合控制链。满队列恢复时允许一个保守气泡，避免为追求一拍而重新引入长反馈路径。

原来的乘加顺序、累加溢出检查、Q31 最近偶数舍入、饱和及尾通道编码没有改变。原窗口地址递推、缓存命中直通、张量精确 LUT 和所有主机端加速继续保留。CMA 分配及运行时保护检查不变；预取队列位于 PL 内部。

## 验证证据及边界

实际 XSim 使用冻结的输入与独立整数参考输出，不重新生成模型或参考结果：

- 真实 128×128 patch：全部 11 节点、15 条命令通过，检查共享 DDR 的前后依赖、尾通道、保护区、AXI 阻塞和最终 B 应答。相对同一 exact-LUT 版本，周期由 1,491,634 降为 1,213,905，减少 18.62%，原/新约 1.229。
- 完整 448×448 平面：全部节点、保护区、尾通道及最终写应答检查通过。相对同一 exact-LUT 版本，15 条命令活动周期减少约 18.76%，原/新约 1.231。只注入初始输入，后续消费实际 RTL 结果。详见构建目录 `sim_448/verification.json` 与交付 manifest；不是实板整张切片加速比。
- 协议回归：缓存卷积、完整内存写回、AXI-Lite 控制三套测试；额外强制 FIFO 满、输出停顿、满队列复位及后续命令重新启动，检查顺序和旧数据清空。
- 板端测速驱动与回传验收流程做独立的模拟接口集成检查，并故意篡改返回节点确认能够拒收。这种软件检查不模拟 FPGA 数学行为；数值证据来自实际 RTL，最终物理板检查仍必须执行。
- 路由资源、setup/hold、时钟和复位/地址检查以交付 `prefetch_manifest.json` 为准。未满足时序、DRC 或仿真要求时不交付 bit。

原始 128 仿真 JSON 中的 `gains` 是对原 flow bit 的历史比较，包含此前 LUT 收益；本次采用 `matched_comparison.json` 中对齐 exact-LUT 的独立对照，不把旧收益重复算到预取上。

这轮不重新训练，也不重新调节检测阈值。保持现有 INT8 输出逐值相同，保证本次执行优化不额外改变检出/误报；这不等于 INT8 与历史 FP32 已经逐值相同，也不构成新的独立临床评价。
