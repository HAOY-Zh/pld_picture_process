## 本轮配置

| 项目 | 固定配置 |
|---|---|
| 网络 | 原2.5D中心检测CNN，13,157参数，不扩宽 |
| 初始化 | 容量对照实验中的小模型续训版 |
| 训练数据 | 247例CT，341个参考结节；包含原53例和新增194例 |
| 校准数据 | 单独保留47例；本训练程序不读取其影像 |
| 新测试数据 | 56例、90个参考结节继续封存，不用于图块准备、训练或选阈值 |
| 训练预算 | 固定30轮，batch 24，Adam，学习率0.0003余弦下降至0.00001 |
| 图块 | 每个参考结节16个位置扰动图块，每例24个随机肺内图块；从每例最多256个网格中选择32个困难背景和16个随机图块 |
| 采样 | 一半概率分给含参考中心的图块；按结节大小和预测肺边缘距离分组平衡 |
| 增广 | XY直角旋转、翻转，Z方向通道反转；中心和偏移标签同步变换 |
| 检查点 | 固定最后一轮，不用校准或测试结果选择训练轮次；每轮保存可恢复断点 |

原53例直接复用已核验的基础和困难背景图块，不重新跑原有推理。新增194例由冻结的原FP32 U-Net预测肺范围，再使用原物理间距、HU和中心/直径标注准备图块；肺模型不训练，LDCT模块不修改。新增困难背景由冻结的旧结节小模型挑选，不增加部署时的网络数量。

原53例的困难背景来自历史教师，新增194例使用当前小模型教师。这一历史差异以及额外训练更新均记录在协议中。因此不能把结果变化完全归因于“病例数增加”，也不能作为严格的数据量单因素对照。

空肺搜索范围的病例仍保留，参考结节附近训练图块仍生成；无搜索网格时另提供一个固定原点背景图块。正式推理必须保持正常的肺范围调度，不允许借用参考位置。

## 运行与恢复

代码：[训练程序](../python/lung_nodule_expanded_training.py)。

工作目录为项目根目录，在PowerShell运行：

```powershell
.\.venv-lung\Scripts\python.exe -u python/lung_nodule_expanded_training.py run
```

本轮已经在后台启动，**不要在进程仍运行时重复执行**。`run`依次执行数据准备和训练；已经准备完成的病例核验后复用，训练从最后一个完整轮次的断点恢复。需要重新运行前，先检查`launch.json`中的进程以及日志，确认前一个任务已经结束。

全部输出位于`data/lung_nodule_expanded_20261020_v1/`：

- `plan.json`和`plan.sha256`：训练病例、协议、初始权重及源码哈希，在训练前冻结。
- `launch.json`：本次启动时间和进程号；进程号只适用于本次运行。
- `run.stdout.log`、`run.stderr.log`：连续运行日志和错误日志。
- `preparation_progress.json`：新增194例图块准备进度；原53例缓存另外复用。
- `training_catalogue.json`：准备完成后生成的图块目录、病例身份及文件哈希。
- `training_progress.json`：每轮损失、更新次数、耗时与运行状态。
- `resume.pt`：完整轮次断点，包含优化器、调度器、混合精度和随机数状态。
- `model.pt`、`model_freeze.json`：仅在30轮训练完成后生成，不能根据任务启动状态就宣称新模型已训练完毕。

GPU混合精度初始缩放固定为32，关闭自动增长。遇到非有限损失或梯度立即报错，不把跳过更新当成正常完成。所有训练图块采用内存映射读取，不将全部原始CT解压到项目目录。

已通过10项单元检查，覆盖原多包数据划分/拒读规则，以及新增训练入口的训练集隔离、重复UID拒绝、采样复现、物理标签一致性、空肺范围保留。

另以新增训练病例的24个真实图块完成一次独立GPU检查：前向、损失、反向梯度和Adam更新均通过，AMP缩放保持32。检查权重已丢弃，不计入正式30轮更新次数；记录见输出目录`training_smoke.json`。

## 训练完成后

1. 先检查30轮是否完成、有效更新次数是否符合预定预算、权重和训练病例身份是否正确。
2. 在47例开发校准上比较旧小模型和新小模型，尽量复用旧输出；以相同的误报预算比较检出率，同时报告原始CNN和固定跨层评分，避免用后处理变化冒充网络提升。
3. 锁定运行阈值后，在既有18例和原45例上做明确标注的开发/历史回归检查。这些数据已经被查看，不再当作新的盲测集。
4. 新56例在模型、评分和阈值固定后另行完成一次全量评价。当前训练脚本没有测试影像读取或测试评价入口。

结果仍以“参考结节检出率＋平均每整卷CT误报数”为主。训练损失降低不是检出效果改善的证据；本轮也不代表已经实现INT8、RTL或FPGA上板加速。
