# 最终版交接和肺结节检测修改入口

本文件的启动方式用于**复用原板端配对和私有便携环境**。如果电脑和板端都没有本项目，请改用 [从零部署与团队协作](从零部署与团队协作_20261027.md)，那里包含系统、依赖、新配对、开机服务、验收和团队合入步骤，不依赖维护者私有包。

后续统一基于 GitHub `main` 修改。原来上传的集成版是 `8a2a855`，本次在它上面整理，原电脑端和板端功能都保留，没有采用后来迁移到板端 PS 的版本。

## 这次增加了什么

- Windows 上位机完整软件包解压后可以双击启动，自动检查运行环境、配对身份和网页，附重新连接与日志入口。
- 基础 FPGA 处理取消了自动再算一遍电脑参考和逐像素对比，实际硬件输出、回执与哈希校验保留。独立电脑功能和执行位置选择还在。
- 新增源码开发启动入口，直接使用私有包内的 Python、依赖和原配套资产，运行当前下载的源码。源码有修改时会打开新的开发实例，避免继续使用已加载旧代码的后台。
- 补齐重打包脚本、验证范围和检测开发入口。

LDCT 100 MHz 和结节批量调度加速原集成版已经包含，这次继续保留。PS 迁移、EDCNN、未完成实板验收的新硬件和其他实验不纳入最终版。肺结节算法、权重和现有板端协议本次没有更换；当前候选分数仍是未校准的实验分数。

## 需要拿到的东西

1. GitHub `main` 的完整源码：可以克隆，也可以通过 Code → Download ZIP 下载后完整解压。不要只下载某个 Python 文件。
2. 私下提供的 `CT_Studio_Final_20261026_01.zip`，完整解压后有 `app/`、`runtime/` 和 `CT Studio 上位机.exe`。这个包基于提交 `dd0655e`，原配对令牌、模型、驱动、bit/HWH 和电脑依赖都在里面，不上传 GitHub。
3. 实际 FPGA 功能需要现有板子在线：电脑能访问 `192.168.2.99:8766`，并且板端仍运行与私有包配套的服务。

**开发时这两份目录分开放。修改 GitHub 下载的源码，用源码根目录的 `start_ct_studio_dev.cmd` 启动。私有包里的 exe 运行的是打包时的源码，不会自动采用外面刚改过的文件。**

不需要另外安装 Python、pip、虚拟环境、模型或 PYNQ 到电脑。新加第三方库时需要自行补进依赖和便携环境；改动网络、量化或硬件协议时，也需要同步配套板端，不能只改电脑端继续使用旧契约。

## 怎么启动和确认

1. 双击源码根目录的 `start_ct_studio_dev.cmd`。
2. 首次弹出目录选择框时，选择完整解压的私有软件包根目录，即同时含有 `app` 和 `runtime` 的那一层。后续会记住，不必每次选择。
3. 程序先显示“当前源码”和“运行环境”路径，再验证模型、配置及配套文件，连接板子后自动打开浏览器。开发网页使用 8110–8120 的空闲端口，与成品软件默认的 8099 分开。

暂时没接板子，可以在源码根目录的 PowerShell 运行离线检查：

```powershell
.\start_ct_studio_dev.cmd -Diagnose
```

也可以明确指定私有包位置：

```powershell
.\start_ct_studio_dev.cmd -DesktopPackage "E:\CT_Studio_Final_20261026_01" -Diagnose
```

离线检查不访问板子、不启动网页，结果在源码目录的 `data/ct_studio_dev/diagnose.json`。正常开发的病例与结果也保存在源码目录的 `data/`，不会写回私有软件包或重装板端。

修改后再次双击开发启动入口。未改源码时复用该源码目录自己的会话；源码变化后另开空闲开发端口，原实例及其任务保留。确认旧实例不再需要后，可以按对应 `data/ct_studio_demo_launcher/<实例>/web.pid` 查找自己的进程并结束；不要结束不确定来源的进程。长时间开发建议关闭不再使用的实例，避免同时占用多份 CT 内存。

板端目标是 `/home/xilinx/ct_test/ct_studio_shared_batch_20261024_01`，服务名 `ct-studio-shared-batch.service`。遇到 403、服务身份不同或连接重置时，先核对现有服务与原配套包，不要运行公开安装器来替代这个配对，也不要同时启动另一个 FPGA 所有者。

## 肺结节检测从哪里修改

| 文件 | 主要内容 |
| --- | --- |
| `python/nodule_detector.py` | 整病例流程入口 `NoduleCaseProvider.run()`；采样、批量 FPGA 调用、输出解码与候选汇总 |
| `python/nodule_vendor/lung_nodule_cnn.py` | 检测配置、搜索区、分块、解码与候选合并：`config_from_dict`、`search_mask`、`tiles`、`decode`、`consolidate` |
| `python/nodule_vendor/lung_nodule_sampling_cache.py` | `sample_patch_reuse()`；图像块插值和采样缓存 |
| `python/nodule_vendor/nodule_plan.py` | `quantize_hu()`、`lower_stem()`、`dequantize_head()`；现有网络输入/输出数值约定 |
| `python/nodule_workspace.py` | 检测任务、进度、取消、病例/原图/增强图来源及候选接入 |
| `python/lungseg/workspace/nodule.js` | 检测操作和结果界面 |
| `python/lungseg/workspace/nodule-viewer.js`、`nodule-common.js` | 三维候选联动和公共显示逻辑 |
| `python/ct_studio_shared_client.py`、`shared_patch_contract.py` | 与板端共享 CNN 的传输及身份校验 |
| `pynq/ct_studio_shared_service.py` | 板端共享 CNN 服务。只调候选阈值/排序/显示时通常不需要修改 |

建议先在现有模型上改候选筛选、阈值、去重、排序和界面，保持 `candidate` 中的坐标、来源和分数含义清楚。当前检测参数从配套包冻结模型的 `detector_config` 读取；单纯修改配置类默认值可能被覆盖，调参应在 `NoduleCaseProvider` 中明确构建新的配置，并让保存的结果记录实际参数。不要改私有包冻结模型 JSON 来绕过身份检查。

涉及采样、量化、输出布局、模型权重或 FPGA 协议时，先明确新的输入输出契约，再同步电脑与板端资产并重新上板验证。这里不保留 PS 迁移路线，也不自动用电脑推理替代 FPGA。

## 修改后至少检查这些

- 基本页面、CT 导入、原图/增强来源切换和原分割/ROI 功能可用。
- 检测候选的 Z/Y/X、物理坐标及三维反选正确；新病例和新来源不能沿用旧候选。
- 批量结果顺序和尾批正确，取消不会发布不完整候选，板端失败不会自动重试推理或回退电脑。
- 能在目标电脑与配套板子上完成实际病例检测，再记录候选变化和耗时。离线通过不代表新检测算法效果或板端稳定性已验收。
