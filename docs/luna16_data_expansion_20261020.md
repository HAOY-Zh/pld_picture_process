## 已完成的接口与验证

- `python/luna16_multibundle.py`：合并已通过的完整审计，检测UID冲突和不同UID的重复像素，保留旧角色并冻结新划分。已有输出目录拒绝覆盖，避免重新洗牌。
- `read_manifest()`：检查清单SHA256、来源/代码保护文件及各压缩包大小与修改时间。
- `records_for(manifest, role)`：读取指定角色的病例元数据。
- `load_development_volume(manifest, uid, role)`：从正确的源包读取完整原生HU，核对像素哈希、形状和物理几何；训练、校准、复核和旧测试角色明确分开，新封存测试影像被拒绝。
- 6项测试通过，覆盖重复UID/像素/标注版本冲突、分层确定性、旧角色保留、多包读取和测试隔离。
- 两个新包各选一例已分配的训练CT验证真实读取，像素SHA256和几何均一致；同一检查确认新测试UID不能通过训练角色加载。没有运行网络。

读取例子（在`python`目录或已设置相应导入路径）：

```python
from luna16_multibundle import OUT, read_manifest, records_for, load_development_volume

manifest = read_manifest(OUT / 'manifest.json')
training_cases = records_for(manifest, 'train')
record = training_cases[0]
hu, geometry = load_development_volume(manifest, record['series_uid'], 'train')
```

原开发读取脚本和旧单包清单保持冻结，没有把它们改成可绕过旧测试保护的版本。已有训练脚本也没有自动改用新队列；本轮完成的是数据准备和可调用的读取接口。
