## 3. 这些时间分别说明什么

| 输出字段 | 含义 |
|---|---|
| `cpu_int8_two_threads` | ARM NEON + OpenMP 双核，相同重排后 INT8 图的推理时间 |
| `pl_resident_network` | PL 完整网络在主机侧的耗时，含输入同步、MMIO 配置、权重加载、等待、最终同步与保护区检查、输出拷贝 |
| `arm_input_quantize_pack` | ARM 上 HU 量化和首层步长重排耗时 |
| `pl_patch_with_input_pack` | 输入为五张 128×128 HU 图像块，输出五张 64×64 检测图，包含上面的重排与网络耗时，以及输出反量化 |
| `pl_engine_active_cycles_ms` | 两个 PL 引擎上报的运算周期之和，按实际 100 MHz 换算；不是端到端耗时 |
| `speedup_same_lowered_integer_graph` | ARM INT8 网络耗时 / PL 网络耗时；双方均不含共同的首层重排 |
| `cma_resident_bytes` | 此结节图常驻 CMA 缓冲区大小，不是整机内存使用量 |

一个图像块包含五层局部 CT 上下文，**不等于一张完整 512×512 切片，更不等于一个病例**。完整病例通常需要几千个图像块。这个测试不能直接与电脑 CUDA、之前约 50 秒/病例，或肺分割单切片时间当作同口径加速比。

此外，输入重排会增加首层输入传输量，ARM 上的搜索区域、采样与三维后处理仍有开销。是否整病例更快，以完整病例测量为准；不能由仿真周期或模型参数少直接断言。

## 4. 实际放在 PL 上的是哪些计算

基于已冻结的 445 例训练权重（13,157 参数、五层输入），没有重新训练：

```text
已有肺分割 → 原生 HU + 预测肺掩膜
    ARM：搜索区、图像块采样、HU→UINT8、步长重排
    PL ：stem0 → stem1 → pool1 → enc1 → pool2 → enc2
                    ↘           上采样拼接 → dec1
                      ↘         上采样拼接 → dec0 → head
    ARM：五通道反量化、中心解码、三维去重、原有跨层评分
    输出：三维候选中心、估计大小、框、分数
```

七层卷积、两次池化、两次最近邻上采样与拼接都调度到 PL，共 **11 个节点、15 条命令**。拼接在张量引擎内融合，不经过 ARM 拼接中间特征。

硬件卷积核原本仅支持步长 1。首层原始 `5→8、3×3、stride=2、padding=1` 采用严格等价重排为 `45→8、1×1、64×64`：在 ARM 上排列输入窗口，在 PL 上计算乘加。没有把 stride 改成 1，也没有改模型结构或训练。重排的边界按归一化零值填充。

中间激活 UINT8、权重逐输出通道 INT8、偏置与累加 INT32、定点乘法/移位四舍六入五成双。最后五个通道分别是中心 logit、dx、dy、dz、对数直径，分别使用自己的尺度、共用零点 128，输出不经过 ReLU，保留负值。它不是肺分割的二值输出，也不是结节轮廓。

沿用已验证的权重复用、本机 C++ MMIO 权重装载、常驻 CMA、设备中间结果、张量融合以及 flow-v1 读写优化。既有肺分割代码、bit 和模型不被改写。

肺分割和结节可以在同一个既有双引擎 overlay 下依次调度；两者会覆盖核内当前驻留权重，因此统一调度必须串行、持有同一把硬件锁。当前独立测速脚本会主动加载一次 bit，不是网页接入实现。

## 5. 整病例检测入口

`nodule_detect.py` 接受已经完成肺分割的原始输入，不会再执行 U-Net。由上游提供同一原生网格：

| 文件 | 要求 |
|---|---|
| `hu.npy` | 原始 HU、INT16、ZYX，完整连续 CT |
| `lung_mask.npy` | 预测肺掩膜、bool、ZYX，与 HU 同形状；不能用专家标注代替 |
| `geometry.json` | `spacing_zyx_mm`、`basis_lps_zyx`、`origin_lps_mm`，和现有候选模块相同的 LPS 几何定义 |
| `case.json` | 输入身份与文件 SHA256，下面的准备脚本生成 |

电脑侧将已有分割输出打包（示例路径需替换为实际路径）：

```powershell
.venv-lung\Scripts\python.exe -X utf8 python\nodule_board_case.py --hu D:\case\hu.npy --lung-mask D:\case\lung_mask.npy --geometry D:\case\geometry.json --out data\nodule_case_01
```

把整份病例目录复制到板端，再执行：

```python
%run /home/xilinx/ct_test/nodule_board/nodule_detect.py --input /home/xilinx/ct_test/nodule_case_01 --out /home/xilinx/ct_test/nodule_case_result_01
```

输出 `prediction.json`，包含候选和搜索、采样、PL 图像块处理、解码、后处理及整病例候选生成时间。计时不包含先前肺分割、输入传输/校验、bit 下载和网页显示。HU/肺掩膜使用内存映射，采样缓存有上限；整病例峰值内存和持续运行仍需实板核查，不能只凭 CMA 估计整机装得下。

## 7. 主要源码

- `pynq/nodule_plan.py`：输入重排、定点约定、模型与包身份验证。
- `pynq/nodule_pl.py`：复用已验证 runtime，独立校验结节图、分配常驻设备缓冲区。
- `pynq/nodule_cpu.py`：相同整数图的通用 C++ ARM 参考封装。
- `pynq/nodule_benchmark.py`：四图像块实板对拍及相同 INT8 图的双核 ARM/PL 对照。
- `pynq/nodule_detect.py`：已有肺分割之后的整病例独立入口。
- `python/nodule_board_prepare.py`：训练图像块校准、INT8 导出与参考生成。
- `python/nodule_integer_reference.py`：独立整数语义参考，不作为硬件测速。
- `python/nodule_rtl_sim.py`：真实共享 DDR 全网络仿真向量与 testbench 生成、XSim 执行与日志审核。
- `python/verify_nodule_board.py`：回传实板结果审核。

所有本次新增代码均独立于网页和既有肺分割实现。
