## 4. 先区分三种调用场景

### 4.1 手动 ROI：完全不需要等 A

```text
电脑已有 CT + 用户画框/指定层范围 + HU 条件 + 可选肺 Mask
    → B 调度 C 的逐层 FPGA 筛选
    → 筛选 mask / count / 可选 HU 统计
    → 电脑汇总面积与体积 → B 展示并联动 MPR/3D
```

没有肺分割结果时可以关闭肺 Mask 条件，仍可使用手动 ROI。B 先用 C 的真实 CPU 参考实现开发页面，明确标成 `CPU_REFERENCE`；硬件就绪后加入 `FPGA` 后端，不把临时实现包装成 FPGA 结果。

### 4.2 候选生成前的初筛：A 先验证规则，再由 C 加速

```text
原始 CT + 已有肺 Mask/搜索范围
    → A 定义、C 实现的逐像素初筛 → 粗候选 seed_mask
    → A 在电脑做跨层连通、尺寸/形状筛选、去重与排序
    → 候选列表
```

这一步发生在候选列表生成之前。首版先全走 A 的软件参考；待 C 硬件初筛可用，再接入同一算法接口。硬件替换软件初筛后，不能又重复执行一遍相同的初筛。

### 4.3 点击候选后的 ROI 定量：复用 C 的底层模块

```text
已有候选列表 → 点击某个候选 → B 根据 bbox 生成 ROI
    → C 按当前 ROI/HU/Mask 条件筛选与计数
    → B 显示统计和三维叠加
```

这是候选生成后的交互分析，与 4.2 是不同调用。候选点击不应无故重跑整卷肺分割或全部候选算法。手动 ROI 与自动 ROI 使用同一套数据契约。

## 5. 三方共同的数据与坐标约定

此节是联调前必须统一的内容。不能各自凭函数参数名称猜测顺序。

### 5.1 图像与 Mask

- 电脑端体数据统一按 `volume_hu[z, y, x]`，形状为 `(Z, H, W)`；单层为 `(H, W)`。HU 使用真实 CT 标度，不能把窗宽窗位后的 8 位显示灰度传给 HU 筛选模块。
- 现有读取结果可能是 `float32`。A 的算法明确自己是否使用原始浮点 HU；C 的硬件首版使用有符号 `int16` HU。送硬件前统一用 `np.rint` 舍入，并检查有限值和 int16 范围；禁止溢出回绕。软件对拍使用同一份转换后的 HU。
- `lung_mask` 和筛选结果统一是同形状 `uint8`，值为 0/1。输入是 0/255 时由边界适配器显式规范化；不是任意非零数都默认合法。使用肺 Mask 时，其空间网格与 CT 必须一致。
- 保留 CT 原生分辨率处理候选和 ROI，不直接使用分割网络的 256×256 输入替代原始 HU。肺 Mask 如来自低分辨率预测，先按既有几何规则恢复到原生网格。
- 肺分割尚未处理的切片标成“未计算”；不能把缺失 Mask 当作全零背景。启用肺 Mask 条件时，只处理已就绪范围或先补齐预测。

### 5.2 ROI、阈值与空结果

- 二维 ROI：`roi_yx=(y0, y1, x0, x1)`。
- 三维 ROI：`roi_zyx=(z0, z1, y0, y1, x0, x1)`。
- 全部是**从 0 开始、左闭右开**的数组索引，对应 `volume[z0:z1, y0:y1, x0:x1]`。例如 `(0, 1, 10, 20, 30, 40)` 是第 0 层的 10×10 区域，共 100 个像素。
- 合法范围为 `0 <= 起点 <= 终点 <= 对应维度`。允许空 ROI，结果 count=0；反向或越界参数报错。UI 如做裁剪，应由 B 显示实际采用的范围，不在硬件适配器里悄悄改参数。
- `hu_range=(low, high)` 两端都包含，且 `low <= high`。第一版建议保留 `use_hu` 开关；关闭后统计 ROI/Mask 内全部像素，而不是用某个“看起来足够宽”的 HU 范围代替。
- 空筛选结果的 HU 均值/最小值/最大值为 `null`，不要显示为 0 HU。未执行、执行失败、成功但计数为 0，是三种不同状态。

### 5.3 索引、世界坐标与体积

沿用现有几何信息：`origin_lps_mm`、`spacing_zyx_mm`、`basis_lps_zyx`。数组索引顺序是 ZYX；世界坐标顺序是 LPS 的 XYZ，单位毫米：

```python
world_lps_xyz_mm = origin_lps_mm + basis_lps_zyx @ index_zyx
```

`basis_lps_zyx` 已包含方向和间距，不能再乘一次 spacing。A 的 MHD/RAW 适配必须核对方向约定并转换到此契约；不能只把 XYZ 参数改名成 ZYX。候选中心可用浮点索引，bbox 用整数半开区间。

当前 MPR 入口对轴对齐 CT 有限制；斜采集或不兼容几何需明确拒绝或显式重采样，并更新坐标和 Mask，不能只改方向字段让页面通过。B 负责把屏幕坐标转换成原生数组坐标；冠状位、矢状位画框不能直接套用轴位的 x/y 下标。

规则正交等间距体数据中：

```text
单个原生轴位切片面积 mm² = 该层 count × spacing_y × spacing_x
筛选区域体积 mm³ = 各层 count 之和 × spacing_z × spacing_y × spacing_x
筛选区域体积 mL = 体积 mm³ / 1000
```

物理量由电脑端根据有效几何计算，FPGA 只需提供 mask/count 等原始统计。非等间距、缺层、重复层等情况先明确处理规则，不直接套一个平均层距。局部层范围的结果标“局部”，不能写成整肺或整卷体积。

## 6. A 的具体任务：先建立可评价的软件候选算法

### 6.1 第一件事：数据读取与坐标自检

LUNA16 参考标注提供中心世界坐标和直径，用于候选匹配；**不等于逐体素病灶分割标签**。不要将按直径画出的球体当成专家分割 Mask 计算“结节 Dice”。若使用数据包中的肺 Mask，要注明它的来源，也要评估实际项目肺分割输出下的结果。

先完成至少以下自检：同一结节在索引切片和世界坐标下定位一致；HU 和毫米尺寸合理；标注只参与评价，不泄漏给候选生成函数。

### 6.2 软件链路与模块拆分

```text
HU + 肺 Mask/搜索区域 + 几何
    → 初筛 seed_mask
    → 跨层连通/合并
    → 尺寸和形状筛选
    → 重复候选合并与排序
    → 候选列表 + 各阶段记录
```

先实验 HU、搜索范围、必要局部结构和形态学规则，再决定哪些有价值。HU 阈值不是已经确定的医学结节标准；不预先硬编码某个区间作为有效算法。开运算、肺 Mask 腐蚀和缩小搜索范围可能删除小结节/贴壁结节，需要逐阶段检查漏检。

建议把接口拆成两部分，方便之后替换前端：

```python
seed_mask = generate_seed_reference(hu, lung_mask, geometry, params)
candidates = finalize_candidates(hu, seed_mask, geometry, params)
```

可再提供统一 `detect_candidates(...)` 包装。C 硬件接入时，前端返回相同语义的 `seed_mask`，后半段继续使用 A 的实现。具体签名写入 A 的模块说明；它们是拟定接口，不是现有可直接 import 的代码。

## 7. C 的具体任务：先做独立 ROI，再扩展候选初筛

### 7.1 第一阶段必须实现的最小硬件

对单层原生 HU 逐像素计算：

```text
keep = 在 ROI 内
       AND（未启用肺 Mask，或 lung_mask == 1）
       AND（未启用 HU 条件，或 low <= HU <= high）

filtered_mask[y, x] = keep ? 1 : 0
valid_count = 所有 keep 的数量
```

第一版输出与输入同大小的二维 mask，ROI 外为 0，便于 B 直接叠加；count 必须与输出 mask 的和一致。一次调用的计数从 0 开始，不能混入上一次调用的结果。

支持原生 512×512 是本项目首先要满足的尺寸；若采用可配置宽高，明确支持范围和打包规则。不把仅在 128×128 仿真通过描述成已经支持真实 512×512 CT。

可选 `sum_hu/min_hu/max_hu` 不阻塞首版 mask/count。若增加累加，明确有符号位宽并证明不溢出；电脑汇总建议使用 int64。第一版未硬件实现的 HU 统计可由电脑按返回 mask 计算，结果中注明计算位置。

### 7.2 给 B 的单层适配器

建议调用形式如下，最终参数名可在 B/C 接口冻结时调整：

```python
result = processor.process_slice(
    hu_slice_i16,
    roi_yx=(y0, y1, x0, x1),
    hu_range=(low, high),
    use_hu=True,
    lung_mask=None,  # None 表示关闭；否则为同形状 0/1 数组
)
```

输出至少有 `filtered_mask`、`valid_count`、`backend`、`status`、实际模式/参数、时间字段和模块版本；有 HU 统计时再增加相应字段。交给调用者的数组不能是随后 DMA 会覆盖的共享视图。

**Python 函数契约不等于总线 ABI。** C 在 RTL/BD 开工前与 B 固定：HU/Mask 如何打包，DMA 每帧字节数，TLAST/边界，配置寄存器或 GPIO 位定义，宽高、ROI、阈值、模式和计数如何读写，启动/完成/错误状态，以及匹配的 IP 名称。不要默认“沿用现有 32 位 DMA”就能自动兼容。

C 交付处理类并接受 B 提供的 DMA、配置接口、缓冲区及当前时钟信息，不自己启动第二个统一服务，不自己加载 Overlay、修改全局 FCLK 或释放服务拥有的资源。若自测脚本需要独占硬件，要单独标明，先停止统一服务。

### 7.3 三维 ROI 如何实现、放在哪台机器

不设计完整三维硬件，也不把整卷 HU 放到板端：

```text
电脑保存 volume_hu 与肺 Mask
    → 遍历 roi_zyx 指定的 z 范围
    → 通过 B 的统一服务提交一张 HU/Mask 和二维 ROI
    → C 的二维模块返回 mask/count
    → 电脑汇总三维 mask、count、HU 统计与体积
```

C 可以提供一个 **PC 端**的 `roi_analyze` 参考封装，逐层处理函数由 B 注入；B 把真实服务调用接进去。C 负责模块语义与汇总参考，B 负责实际网络、任务取消、进度、缓存和 UI，不再创建另一套 HTTP 协议。

完整 `mask_3d` 如返回，统一为原生 `(Z,H,W)`、范围外为 0，保存在电脑；若采用局部返回，必须携带 `bbox_zyx`，不能让 B 猜偏移。板端只保留受控切片/小块缓冲。

### 7.4 A 规则冻结后的候选模式

手动 ROI 模块先独立验收。收到第 6.4 节交付包后，C 再判断已实现的 ROI/Mask/HU 算子能复用多少；全图 ROI 可直接复用基础筛选。新增局部算子必须按 A 的软件定义实现，不无条件增加复杂形态学。

候选模式与手动 ROI 模式使用不同的 `algorithm_id/params_version`，注明输出到底是 HU 筛选区域还是候选 `seed_mask`。若时间不够，保留 A 的软件初筛和已验证的 FPGA ROI，不让未完成的候选硬件阻塞全项目。

### 7.5 C 的模块验收清单

- 独立软件参考与硬件逐像素一致，count 与 mask 求和一致；未对拍不能只凭“看起来相同”通过。
- 测试空 ROI、单像素、全图、图像边界、阈值相等/端点、负 HU、全零/全一肺 Mask、连续不同参数调用；非法输入在启动 DMA 前拒绝。
- RTL 仿真、综合、实现时序、真实板端验证分别标记，不互相替代。
- 保存实际输入和实际输出数组、参数、比较结果、运行命令、bit/HWH 哈希和原始日志。
- 报告 LUT/FF/BRAM/DSP、目标与实际时钟、对应约束下的 WNS/WHS；未做多频率验证不声称已测得 Fmax。
- 报告可测的模块时间和测试条件。若只测到 DMA 启动至完成，写 `DMA+计算`；没有硬件计数器或独立测量，不拆出虚构的纯 PL 时间。
- 连续调用确认不累积 CMA、不残留旧 count、不覆盖已返回结果。异常时上报给 B 的资源管理层。

## 8. B 的具体任务：统一平台、LDCT 和最终展示

### 8.1 先接管现有基线，再增加新入口

先在自己的电脑启动第 2 节网页，并取得实际 FPGA 运行资产。复现现有基础处理、分割和 MPR/三维路径后，再增加 ROI 与候选入口。保留原有窗宽窗位、阈值结果、形态学输入以及 CPU/FPGA 标签的已有语义，不为接入新模块把基础功能改乱。

ROI 页面可以先连接 C 的 CPU 参考，允许没有开发板时开发与自检。用户主动选择 CPU 时显示 `CPU_REFERENCE`；选择 FPGA 后失败就显示失败，不静默转 CPU，更不能继续显示 FPGA 的时间。

### 8.2 ROI 与候选展示的最低要求

1. 手动框选原生轴位 ROI，设置 z 范围、HU 条件及是否使用肺 Mask；显示实际采用的索引范围。
2. 显示筛选 mask、count、各层面积/总筛选体积及有效 HU 统计，注明单位、是否局部和计算后端。
3. 候选列表显示位置、粗区域大小、分数含义；点击后同步切片、十字线、ROI 与三维标记。
4. 自动 ROI 来自候选 bbox；如增加边距，说明毫米/体素转换，并与手动调整结果区分。
5. ROI 与候选变化后，标注旧结果已过期；记录 CT、参数、肺 Mask、算法及硬件身份，防止错例叠加。
6. 三维上区分肺表面、候选标记和 HU 筛选区域。存在三维 ROI 不等于实现了三维神经分割。

首版先支持轴位画框 + z 范围 + 三平面定位。直接在任意 MPR 平面画框、复杂旋转 ROI 等可以后置，不阻塞主链路。

### 8.3 LDCT 的交付边界

按既有 LDCT 交接文件接入真实 HU→HU 模块。先接稳定的 50 MHz 版本；100 MHz 作为有时间上限的优化，必须重新实现、检查时序并实板验证，不能仅修改 FCLK 或把原耗时除以二。

明确 tile/halo、拼接、边界与数据位宽，按整张 CT 统计实际时间。权重固化在 ROM 的版本，更换模型时必须重建匹配 bit，不能只替换权重文件。

LDCT 先独立展示配对数据的增强质量和时间。候选首版先跑原始 CT；没有同病例病灶/分割参考时，不宣称增强提高了检出或 Dice。Mayo、LCTSC、LUNA16 等数据分别说明用途，不拼成同一个患者流程。

### 8.4 唯一资源管理层

B 统一拥有板端硬件，负责：空闲确认 → 切换 bit → 设置并核对时钟 → 初始化匹配 DMA/缓冲 → 调用模块 → 收集结果。C/LDCT/分割处理类只使用借用的资源。

切换前确认没有任务或未完成 DMA；发生超时/错误时标为故障，不直接释放可能仍被 DMA 使用的内存，不自动重试或强行切 bit。由统一管理层按明确流程恢复。PC 上已完成的结果可继续浏览，但不能把它当成当前硬件仍健康。

### 8.5 整机验收和发布

从重启板卡、启动唯一服务开始，依次验证基础处理、LDCT、分割、手动 ROI、候选、自动 ROI 和三维联动，再反向切回已有模块。检查冷/热启动、切换耗时、内存与 CMA、连续任务、取消/失败状态、网页响应和结果身份。

B 维护发布清单：源码提交、Python 依赖、每个模块 bit/HWH/模型/配置哈希、实际频率、启动命令、所需数据与凭据的获取方式、已验收和未验收项。令牌不写入公开仓库或文档。

## 9. PYNQ-Z2 能否装下：统一的运行策略

默认采用 **一块 PYNQ-Z2、一个板端服务、多个 bit 按阶段运行**。不要求所有 IP 同时塞进一个 bit，也不把各自综合报告的简单相加当成已经实现整机。

PYNQ-Z2 的 PL 资源和 512 MB DDR 都有限。仅一份 `512×512×300` 的 float32 HU 就约 300 MiB，还未算 Python、Linux、模型与 DMA 缓冲。因此：

- CT 整卷、肺 Mask、跨层连通域、候选排序、MPR 和三维数据留在电脑。
- 板端逐层/小块处理，B 限制缓存大小；C 不申请随 CT 层数增长的 CMA。
- 同一阶段尽量批量执行，例如先完成分割，再完成所需层的初筛；避免每张切片在多个 bit 之间来回切换。
- 已有分割、基础处理和 LDCT 的时钟要求分别记录，切换时使用本模块已验证频率，不默认全项目 100 MHz。
- 若研究同 bit 集成，另行出布局布线、时序和真实运行证据；不能阻塞多 bit 方案交付。

几何变换/配准保留为已有可选拓展成果。有真实对齐需求再接入；本轮 C 的必做主线是 ROI/计数及可复用初筛，不再同时新增一条完整配准主线。

## 10. 性能与效果怎么记录，避免“模块快但点按钮慢”

每份结果至少记录后端、输入大小、ROI/层范围、版本、实际频率、冷/热状态、重复次数与计时范围。建议分层记录：

| 时间 | 计时范围与含义 |
| --- | --- |
| 准备时间 | HU 转换、打包等 CPU 工作 |
| 模块时间 | 明确是纯 PL 计数，还是 DMA+计算的实测区间 |
| 切换时间 | Overlay 下载、时钟与资源初始化，单独记录 |
| 请求时间 | 电脑到板端往返，注明是否包含准备/切换 |
| 交互端到端时间 | 用户应用处理到结果真正显示完成，包含网络和浏览器渲染 |

上述时间可能包含/重叠，不能不加说明直接相加。FPS 也要写对应的是模块吞吐还是整机交互吞吐。

公平的 FPGA 加速对照使用相同输入、规则和输出：CPU ROI 参考对 FPGA ROI；候选算法的软件初筛对 FPGA 初筛，后半段保持一致。同时报告纯模块与端到端收益。单张很小 ROI 可能受通信开销主导，测不到整机加速就如实报告，并考虑批量处理。

若展示已有分割剪枝/INT8/PL 编程优化，分别保留原始与剪枝模型、FP32/INT8、CPU/PL 的对应对照；不能将模型变化、量化和硬件执行收益全部归给 FPGA。新模块报告不改写旧实验的测量口径。
