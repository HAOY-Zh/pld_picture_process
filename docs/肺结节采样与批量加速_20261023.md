# 肺结节采样与批量加速（2026-10-23）

上一轮同一张 512×512 中央层、32 块的实板结果：原 ARM 约 4.660 秒、原 PL 约 4.828 秒。PL 流程中采样约 2.089 秒、量化重排约 0.923 秒、网络及调度约 1.486 秒。此次针对这些实测瓶颈修改执行方式，不改模型权重、量化尺度、bit/HWH、空间网格、候选阈值和评分器。

**本轮本地验证与真实 RTL 仿真已通过，优化后的板端耗时尚未测得。**

## 1. 这次改了什么

### 共享采样

原来按每块、每个原生 Z 平面做二维插值，重叠区域反复计算。现在在当前层所有块的包围矩形内共享插值结果，保留完全相同的全局坐标、SciPy float32 双线性插值、Z 混合、舍入和 INT16 输出。

当前真实输入中，32 块涉及 3 张原生层，原来需要 96 次局部插值调用；新流程只做 3 次共享矩形插值。块视图直接从共享上下文中切出，不再为每块重复采样或分配相同内容。共享上下文约 2 MB，生命周期仅为一个检测平面。

这不是预先把检测输入存好再漏计处理时间：每次正式计时都会重新生成共享采样上下文。上传包只有原生 HU 薄层和旧搜索掩膜，采样仍在板端在线执行。

### 精确查表量化与 C++ 重排

原来每块通过 NumPy FP64 量化、多次临时数组和补边，生成 45 通道 CHW，再转换为硬件 HWC8。

现在使用由冻结公式生成的 INT16 全范围查表，在 C++ 中直接生成 ARM 所需 CHW，或写入 PL 常驻输入 CMA 的 HWC8。保持局部块边界的零填充和尾部三通道零值。支持只读、非连续的共享上下文块视图。

65536 种 INT16 值、正负值、边界补零和尾通道均与旧输入逐字节对拍。查表位于 ARM 内存，不新增 FPGA LUT/DSP。

### 同一层权重跨图像块复用

原来一块执行完整网络，再换下一块；每块都重新加载 11 个卷积输出通道块。

现在每批默认 8 块，按网络节点和输出通道块执行：加载一次该组权重，连续计算这 8 块，再换下一组权重。所有中间特征仍由 PL 写入 DDR，ARM 不参与卷积、池化、拼接。

对于此次 32 块：

| 项目 | 旧流程 | 默认 batch=8 |
|---|---:|---:|
| 网络计算与硬件命令 | 480 条 | 480 条 |
| 权重块装载 | 352 次 | 44 次 |
| 传输权重包 | 6560 个 | 820 个 |
| 常驻 CMA | 519680 字节 | 4157440 字节 |

权重装载减少 8 倍，不表示完整流程必然提速 8 倍。乘加次数、DDR 中间特征总量和算子命令数量没有减少。常驻 CMA 约 4 MB，不代表整病例总内存。

每个输入槽都保留保护区；只刷新 ARM 写入的输入，不把旧 ARM 缓存写回设备中间结果。检查所有输出计数、完成序号、保护区与未调度槽。超时后保留仍可能被 AXI 使用的内存并拒绝继续复用。

## 2. 上板直接做四组对照

保留之前已能正确运行的 `/home/xilinx/ct_test/nodule_board`。新包为独立的 `nodule_fast` 文件夹，不覆盖它。

电脑 PowerShell：

```powershell
& "C:\Program Files\Git\usr\bin\scp.exe" -r "D:\pld_picture_process\data\nodule_fast_20261023_v2\nodule_fast" xilinx@192.168.2.99:/home/xilinx/ct_test/
```

板端 Jupyter：

```python
%run /home/xilinx/ct_test/nodule_fast/nodule_fast_benchmark.py --runs 3 --warmup 1 --batch-size 8 --out /home/xilinx/ct_test/nodule_fast_speed_01
```

脚本对同一张原始第 52 层、相同 32 块，依次运行：

1. `baseline_ARM`：原采样、原输入处理、ARM 双核网络。
2. `optimized_ARM`：共享采样、C++ 查表重排、同一 ARM 双核网络。
3. `baseline_PL`：原采样、原输入处理、原逐块 PL 调度。
4. `optimized_PL`：共享采样、直接 HWC8 输入、批量权重复用 PL 调度。

四组均先预热再测。所有块的五通道输出都与第一组逐元素核对，出现不同就报错、作废本次计时，不悄悄换算法或改回 CPU。每完成一组会保存该组 JSON，最后保存 `result.json` 和 `plane_predictions.npz`。

核心比较：

- `gains.pl_before_after`：同板原 PL / 优化 PL 的完整切片耗时。
- `gains.arm_before_after`：同板原 ARM / 优化 ARM 的完整切片耗时。
- `gains.optimized_arm_vs_pl`：双方都使用新预处理后，ARM / PL 的完整切片耗时；小于 1 仍说明 PL 更慢，应如实报告。

`--batch-size 1` 可作为只优化输入、不跨块复用权重的补充实验；用新的结果目录运行。默认先测 8，避免不必要增加内存。不要同时启动其他 FPGA 服务。脚本只加载原 bit 一次并使用此前验证的 100 MHz，不超频。

板端需要现有 g++ 和 PYNQ/NumPy/SciPy，不需要 PyTorch、SVM 或联网安装依赖。C++ 原生库在板端首次编译，并校验源文件与已编译二进制身份。

## 3. 测速范围保持一致

完整切片时间包含在线采样、输入处理、全部网络执行、解码和层内候选合并。仍不含先前肺分割、预先构建的搜索掩膜与块列表、文件读取、bit 下载、最终整病例跨层评分或网页显示。

新 `input_pack_ms` 还包含直接写 HWC8 的操作，这部分在旧流程归入网络输入打包，所以单个分项的边界有所移动。**判断收益以包含全部阶段的 `slice_sampling_to_candidates_ms` 为主，不能只挑变短的网络分项。**

该层肺面积最大，不代表每张切片的平均速度；不能将单层加速比直接写成整病例加速比。本地电脑上的检查或微基准也不作为板端速度。

## 4. 整病例入口

`nodule_fast_detect.py` 可接原 `nodule_board_case.py` 生成的完整病例输入：原生 INT16 `hu.npy`、同网格预测肺 bool 掩膜、几何和文件身份记录。不会重复运行肺分割。

```python
%run /home/xilinx/ct_test/nodule_fast/nodule_fast_detect.py --input /home/xilinx/ct_test/nodule_case_01 --out /home/xilinx/ct_test/nodule_fast_case_01 --batch-size 8
```

内部按检测平面分组，共享该层采样并批量推理，保留原始块的解码顺序，最后才做原有全体积 NMS 与跨层评分。没有把单层提前去重插入整病例算法。

输出既有整病例时间，也有各检测平面原始候选生成时间。`amortized_ms_per_original_slice` 是整病例耗时除以原始切片数，明确属于折合平均，不是每一张独立测得的延迟。检测平面通常以 1.25 mm 递进，不等同于原生切片数。

这个整病例入口仍需实板验证速度、峰值内存与稳定性。此次完整切片实验不能代替它，也不能将历史 FP32 检出率自动套给 INT8。
