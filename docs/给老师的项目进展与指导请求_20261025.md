# 低剂量 CT 增强与智能分析辅助系统

**项目进展与指导请求｜2026 年 10 月 25 日**

老师您好！我们正在基于 PYNQ-Z2 开发一套医学影像处理与辅助分析系统。目前主要功能已能在网页中联动运行，想请您帮我们看看项目方向、创新点和后续完善重点是否合适。

## 一、我们希望解决什么问题

围绕肺部 CT，形成“图像增强—肺区分割—可疑结节定位—局部定量观察”的完整流程。使用 FPGA 承担已部署的图像处理和神经网络计算，电脑负责病例管理、部分后处理、交互和三维显示。

项目采用三个用途不同的轻量网络：**CNN 做低剂量 CT 增强，U-Net 做肺区分割，2.5D CNN 做结节可疑候选检测**。肺分割为检测提供搜索范围，检测结果进一步驱动自动 ROI、MPR 和三维定位；目前不将候选检测称为精确病灶分割或诊断。

## 二、目前已经完成的内容

| 模块 | 当前进展与用途 |
|---|---|
| 影像输入与基础处理 | 以 DICOM CT 为主要输入，兼容符合 CT HU 和空间几何约定的 NIfTI、NPZ（非任意文件）；实现窗宽窗位、HU 阈值、形态学等处理，保留直方图和伪彩展示，按实际执行位置区分电脑参考与 FPGA 输出。 |
| LDCT 增强 | 轻量 CNN 已上板并接入网页，可对照原 CT 与增强输出，选择对应 HU 来源继续分析。增强是否改善后续分割和检测，仍需配对实验验证。 |
| 肺区分割与三维 | U-Net 已完成 INT8 部署和剪枝候选验证，可进行整组分割、肺三维重建及轴位、冠状位、矢状位观察。 |
| 肺结节候选检测 | 约 1.3 万参数的五层输入 2.5D CNN，利用肺区限制搜索范围；已接通整病例 FPGA 实验检测。当前整机候选仍需进一步筛选和质量评价。 |
| ROI 与多视图联动 | 选择候选后可同步列表、切片、MPR、肺三维标记和自动 ROI，并支持局部 MIP 观察。 |
| 局部定量与统一平台 | 支持 HU 范围筛选、肺掩膜约束和连续层统计；FPGA 汇总计数、HU 和、平方和、最小/最大值，电脑计算均值、标准差与几何量。网页统一管理任务、进度、停止和导出。 |

ROI 统计的是所选区域在相应筛选条件下的体素与 HU 信息；目前没有结节真实轮廓，因此不把框内体积当作精确结节体积。

## 三、已有的主要结果

### 算法效果

- **肺分割：**原冻结模型在 17 个可用留出病例、2,705 层上的平均病例 Dice 为 **0.9655**。这是历史软件精度评价，不能理解为诊断正确率，也不能直接替代当前整机版本的全流程验收。
- **结节检测：**使用 LUNA16 数据，当前模型以 445 例训练、75 例开发评价；在固定模型、跨层评分及开发阈值后，113 例留出测试、175 个参考结节中检出 154 个，**检出率 88.0%，平均误报 4.89 个/整套 CT**。这是电脑 FP32 加冻结评分流程的历史结果，不是当前 FPGA 原始候选链路的成绩，也不是官方十折成绩。
- **LDCT 增强：**已有实际增强输出，下一步需要补齐固定配对测试集上的图像质量评价，不能仅凭视觉效果就宣称增强提高分割或检测精度。

### FPGA 与整机效率

- U-Net 与结节 CNN 已共用同一个 100 MHz 卷积/张量引擎，通过更换权重和命令依次运行，无需在这两个模型之间重新下载 bit。22 次实板模型调用中，**342 个节点数组与冻结整数参考逐值一致，822 项其他模型驻留缓冲哈希检查通过**。
- 共享引擎占用 **17,865 LUT、20,063 FF、80 DSP、31.5 BRAM tile**。这是这一套引擎的资源，不是基础处理、LDCT、ROI 等所有模块同时放入一个 bit 后的总资源。
- 指定 256×256 输入的原始/剪枝 U-Net 网络调用平均为 **431.6/395.4 ms**，不含完整病例预后处理、传输和显示。优化包括量化、剪枝、缓存和流水调度，不能将全部收益都归因于某一项。
- 最新团队集成记录：同一份 **386 层、512×512 CT** 的整病例候选检测，经批量传输和调度优化，由 **696.98 s 降至 431.29 s，耗时减少约 38.1%**；请求数由 5,237 次降至 655 次，计算 patch 数仍为 5,237，优化前后输入、网络输出与候选结果一致。

上述一致性说明实现和优化没有改变对应测试输入的结果，不等于这些结果已经具有足够的医学检测质量。最新整机这例输出 **8,288 项原始实验候选**，并非 8,288 个真实结节；它与历史“筛选后平均误报 4.89 个/CT”的评价阶段不同，仍需核对整机评分、筛选与后处理的一致性。

## 四、我们认为可以重点呈现的特色

1. **围绕同一 CT 数据形成完整操作链。** 肺区结果限定结节搜索，候选直接带动自动 ROI 与三维观察，减少重复定位和无关区域处理。
2. **面向小型 FPGA 的轻量化与资源复用。** 使用 INT8、结构化剪枝、权重预打包、常驻缓冲、缓存及流水重叠，让不同网络复用同一计算引擎。
3. **同时关注硬件内核和整机体验。** 除计算周期外，还优化电脑与板端传输、批量调用及调度，并分别记录模块耗时与整病例耗时。

我们目前更倾向把特色落在上述软硬件协同和完整应用流程上；这些工作能否形成足够鲜明的竞赛创新点，希望请您判断。

## 五、目前的不足与后续计划

当前优先级是**把已有功能做可靠、把检测结果做可用，并补齐统一评价**：

- 优先核对整机结节评分、跨层合并和筛选流程，减少原始候选数量，在固定阈值下同时报告检出率与平均误报。
- 验证量化、预测肺掩膜和整机后处理对检测质量的影响，明确软件与板端结果能否对应；不直接沿用历史精度作为新版本成绩。
- 补 LDCT 配对质量指标、同模型 CPU/FPGA 对照、资源和时序报告，以及端到端运行记录。
- 完善连续运行、模块切换和异常恢复，确认三维与 ROI 的坐标、病例身份和来源始终一致。
