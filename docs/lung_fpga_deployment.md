## 硬件整数规范：与电脑 x86 后端不是同一个证明

源码：`python/lung_fpga_contract.py`。当前正式导出为
`data/lung_fpga_readiness_20261014/integer_contract_v3/`。
首次导出因旧层别名 `bottleneck.3` 而中止，实际应为 `neck.3`；失败记录保留在
`integer_contract/failure.json`。v2 为中间版本；后续 RTL 使用 v3。

| 内容 | 冻结约定 |
| --- | --- |
| 激活 | UINT8 仿射，0..255；减零点后须支持有符号 9 位 -255..255 |
| 权重 | 有符号 INT8，按输出通道缩放，权重零点必须为 0 |
| 累加/偏置 | INT32；溢出视为错误，不允许回绕；bias 采用最近偶数舍入 |
| 重新量化 | 每输出通道 Q31 乘数及右移；有符号乘积先用 64 位参考 |
| 舍入 | 一次有符号 round-to-nearest ties-to-even，不做两阶段舍入 |
| 饱和/ReLU | 加输出零点后限到 0..255；融合 ReLU 最低值为输出零点 |
| 边缘填充 | 真实零对应输入零点编码，不能总填编码 0 |
| MaxPool | 2×2、stride 2；取最大编码，量化网格不变 |
| 最近邻放大 | 每个编码复制成 2×2，量化网格不变 |
| skip concat | 两分支分别重缩放到目标网格；先放大的 decoder，再 encoder skip |
| 特征图/权重布局 | CHW，X 最快；OIHW，KX 最快；多字节整数小端 |

核心数学：

```text
acc[o] = sum((qx - zx) * qw[o]) + bias_int32[o]
bias_int32[o] = RNE(bias_fp32[o] / (sx * sw[o]))
ratio[o] = sx * sw[o] / sy ~= multiplier[o] / 2**right_shift[o]
qy[o] = clip(RNE(acc[o] * multiplier[o] / 2**right_shift[o]) + zy, 0, 255)
```

累加保守上界最大 7053984，小于 INT32 上限；权重本体 121616 字节，
896 KiB skip 缓存不是片上最小需求或整机内存需求。
`parameters.npz` 导出 15 层权重、整数偏置、逐通道乘数/右移，
`contract.json` 给出卷积形状、concat 分支缩放、布局和来源哈希；
`operator_vectors.npz` 给出每层真实零/ramp127/ramp255 三组共 45 组算子向量，
同时保存精确整数累加、参考输出和 x86 输出，不使用医学图像或人工标签。

### 实际数值差异，必须保留

每组输入范围共比较 22592 个输出编码：

- 真实零向量：与 x86 输出全部一致。
- ramp127：2 个编码不同，最大差 1。
- ramp255：1340 个编码不同，最大差 49。

不是所有差异都能归结为“无害的舍入误差”。整数偏置/Q31 路径与 x86 内核不完全相同，
满范围激活的后端行为也需分析；当前没有证明具体差异全部来自哪一种内部实现。
CPU 校准的 reduce_range **不等于**运行时所有编码都硬限到 127，
不得为了让对拍通过，私自把硬件输出范围改成 0..127。

实际激活补充抽查：同样固定 19 张验证切片，285 个卷积层内中心区域，
比较 241984 个输出编码，31 个不同、最大差 1；150 个层内探针输入出现 >127 编码。
原生层内中心 8×8 输入取 3×3 卷积的内侧 6×6 输出，1×1 卷积比较全块，
避免把裁下来的块边界当成原图零填充。没有读取人工标注或根据得分挑层。
记录在 `integer_contract_v3/native_operator_probes.json`。
仅局部算子抽查，没有传播定点差异，也不是整网定点精度验收。

这就是导出中 `hardware_ready=false`、`whole_network_fixed_point_validated=false`
以及 `x86_bit_exact_on_probes=false` 的原因。需要继续跑拟采用规则的完整网络，
在同一验证集比较最终掩膜/精度，不能直接把本轮 CPU 的 Dice 当作 RTL 的 Dice。

## 缓存与资源方向

PYNQ-Z2 有 220 个 DSP、630 KiB 原始 BRAM 容量和共享的 512 MB DDR。
依据：[TUL 板卡说明](https://www.tul.com.tw/images/PYNQ-Z2_PA_v2_pp_20201209_STD.pdf)、
[AMD Zynq-7000 DS190](https://www.amd.com/content/dam/xilinx/support/documents/data_sheets/ds190-Zynq-7000-Overview.pdf)。
单 DSP48E1 提供 25×18 乘法和 48 位数据通路，但 32×31 重新量化乘法不是单个
9×8 MAC 的资源成本；须单独规划。
[AMD UG479](https://docs.amd.com/v/u/en-US/ug479_7Series_DSP48E1)

采用一个可配置卷积引擎，逐层复用，不展开 15 套引擎。
DDR 保存层间工作图、三个 skip 和权重；BRAM 放 tile/行缓存和局部累加。
初始工程探索目标：64 个 MAC lane、少量共享重新量化单元、100 MHz 目标时钟，
并保留 DMA/控制和基础处理的资源余量；尚无综合结果，不能保证达到目标。
665845760 MAC/切片除以理想 64 MAC/周期、100 MHz，得到计算下界约 104 ms；
这没有计算传输、重缩放、访存停顿等，**不是实测延迟或 9.6 FPS 的承诺**。

先验证板上逐切片网络核心。PS 管理数据、归一化、DMA/调度、原生概率恢复和初期人体约束；
电脑负责浏览器 3D/MPR 和初期整例三维清理。
之前建议三维清理放 PS 只是最终分工方向，不是可直接复制当前 SciPy 程序的证明：
240×512×512 的 INT32 标签本身约 240 MiB，再加原 HU/掩膜等可能超过可用 DDR。
全体积 PS 清理需要压缩/分块连通域和实测内存方案，后续单独实现；不能依赖整例同驻内存。
