## 执行方式

已处理的30例复用数值缓存，不重跑肺分割、LoG或Hessian。新60例首次计算肺掩膜与候选；原始HU按需读取，不复制出大量原卷数组。

运行环境为 `.venv-lung`。电脑只有16 GiB物理内存，启动时可用空间约2 GiB，因此GPU肺掩膜阶段与CPU候选阶段分开串行执行。CPU候选在各阶段完成后释放体积种子数组，与原v4算法的候选、坐标及41维描述已通过严格等价测试；不改变任何筛选参数。

新增脚本：

- `python/lung_candidate_expand.py`：冻结安排、掩膜生成、内存受控候选与局部描述、断点续用。
- `python/lung_candidate_expand_train.py`：72例内部训练、参数比较、冻结阈值、12+6例复核及90例完整覆盖审计。

## FPGA 适配判断

当前适合实现为PS/PL协作模块，不能把现有Python整体视为可直接综合的IP。

[PYNQ-Z2厂家资料](https://www.tul.com.tw/images/PYNQ-Z2_PA_v2_pp_20201209_STD.pdf)列出220个DSP、630 KB块RAM和512 MB DDR3。一张512×512、16位切片本身需要512 KiB，三张就需要1.5 MiB，已超过片上块RAM；因此三维处理应使用行缓存、分块和外部DDR。作为量级示例，32³个16位体素需要64 KiB，但真实ROI必须由物理半径、spacing和滤波halo决定，不能把所有结节强行裁成固定32³。

| 计算环节 | 优先位置 | 原因与限制 |
|---|---|---|
| HU判断、局部高斯平滑、差分梯度 | PL | 固定邻域和乘加，适合流水线与行缓存；需处理物理spacing、边界、定点误差 |
| 特征的求和、平方和、计数 | PL | 可并行归约；必须验证累加位宽与溢出 |
| 固定方向的局部采样 | 先PS，后比较PL收益 | 插值有固定算术，但三维取样地址不连续，搬运成本可能占主导 |
| 连通域、候选管理、中心合并与NMS | 先PC/PS | 不规则访问、可变候选数和控制分支较多 |
| 百分位数、协方差特征及特征选择 | 训练/参考端优先 | 百分位数和特征值运算并非廉价逐像素算子；若替换为近似必须重新评价效果 |
| SVM训练、参数搜索 | PC | 属于离线工作，无需占用板端推理资源 |
| 导出的16维小型SVM推理 | 先PS | 可先用NumPy参考；RBF包含指数计算，是否搬PL需根据实际耗时决定 |

原始CT整卷保留在电脑，板端按切片或ROI分块处理并复用DDR缓冲；避免整卷常驻PYNQ内存。现有LDCT和U-Net保持原模块接口，不新增第三个CNN。

扩大训练可能改变支持向量数量，板端计算量必须按最终模型重估。本轮没有新增RTL、综合、时序或板端测速。CPU候选耗时、GPU肺分割耗时和局部分类耗时分别记录，不能用其中一项冒充FPGA或网页端到端加速。

## 用户关注的实际应用耗时

新CT仍然需要肺分割、候选初筛、特征计算和SVM评分。只有训练、参数搜索和特征选择属于无需在每个新病例重做的离线工作。当前耗时的全卷候选提取不是训练结束后就会消失的开销。

用户指出U-Net看起来更快，这与日志一致：同一例481张切片，肺分割阶段约17.4秒、候选和手工特征约94.8秒。前者是带预后处理的原FP32 CUDA参考流程，后者是CPU流程；这不是相同后端的模型速度比较，也不是网页实际部署的剪枝INT8 PL模型时间。它反映的是当前参考系统的耗时分布，不能以SVM模型小就推断整条路线轻量。

此前小样本实验大量复用了候选及数值特征缓存，没有重新跑整卷LoG/Hessian。缓存评分时间不能用作新CT的完整推理时间。

为避免重跑，用户要求关注性能后，仅给后续执行增加了 `stage_timings_ms`；已在运行的48例仍执行原始源码。计划分组、算法算式、参数网格和阈值政策均未改，原计划及原始源码完整保留，计时修订见 `plan_revisions/timing_only_v2/`。新12例将记录滤波种子、区域处理、Hessian、局部测量、候选合并和球壳特征各阶段耗时。必须先看这些实测占比，再判断哪些步骤值得硬件化。

当前方案还没有证明达到可用的应用延迟，也没有证明比轻量CNN路线更快。后续选型需把准确率、完整推理耗时、内存及硬件成本一起比较。
