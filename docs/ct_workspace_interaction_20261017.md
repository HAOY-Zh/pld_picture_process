# 基础处理输入、显示与计时修正

本轮解决三个问题：形态学隐式进行HU阈值、编辑输出窗参数同时改变左侧参考图、性能主数字只显示DMA/PL局部耗时。

## 二值分割与形态学

- HU范围阈值是独立方法，唯一显示可编辑的HU上下限。
- 腐蚀、膨胀、开、闭运算显式使用同病例、同切片最近一次保存的阈值二值结果。无匹配结果时禁用执行，后台也会拒绝，不能仅绕过按钮直接调用。
- 界面显示原CT、已保存二值输入、形态学结果；每个结果保存输入结果ID、掩膜SHA、来源后端和原阈值参数。开、闭操作各自从该二值输入开始，不隐式串接上一轮形态学输出。
- 改变HU控件不会改变已经选定的二值输入。需要改变输入时，返回阈值方法重新生成；切片或病例变化后不能误用旧掩膜。
- 当前硬件为二值形态学、3×3核，各阶段零填充，未新增灰度形态学硬件。
- 为兼容已上传的板端包，线上请求仍发送原HU和已保存阈值参数，由板端PS复现同一二值输入，然后PL执行形态学。电脑会先验证复现掩膜逐像素等于已选掩膜，使用已保存掩膜独立计算形态学参考，再校验真实PL输出。当前未增加任意外部掩膜上传接口。

## 窗宽窗位显示

CT原始HU需要映射才能在屏幕显示。左侧固定采用WL=-600、WW=1500作为显示参考，明确标记，不随待应用窗参数变化。

选择肺窗、软组织窗、骨窗或自定义参数后，点击应用才生成右侧处理结果；右侧标题标出实际使用的WL/WW。直方图、伪彩同样使用输出窗设置；二值操作不显示无关的窗控件。原HU及分割输入均不改变。

## 性能范围

| 字段 | 范围 |
| --- | --- |
| processing_ms | 实际PL/DMA阶段（含DMA传输与驱动轮询），或明确选择的电脑参考运算。不是纯核延迟，也不是网页总延迟。 |
| hardware_receipt.stats.overlay_switch_ms | 切换bit、配置解析、缓冲准备等，复用同方法时可为0。 |
| hardware_receipt.roundtrip_ms | 电脑发起板端请求至完成回复解析校验，包含板端切换、准备、DMA及协议开销。 |
| host_result_ready_ms | 电脑接收任务至图像落盘，含线程调度、独立参考、板端往返、校验及NPZ保存；不含最后JSON回执写入和浏览器取图显示。 |
| browser_display_timings[].click_to_display_ms | 当前浏览器点击应用至结果绘制后的下一帧，包含状态轮询和取图。属于网页响应测量，不作为硬件FPS。 |

这些范围嵌套，不能相加。浏览器计时只绑定对应的界面请求和结果ID；刷新后没有该次点击记录的旧结果显示空值，不从硬件计时推算。通过网页导出时附带该浏览器的计时记录。

用户本次已有实际回执举例：最近一次腐蚀DMA/PL约18.206ms，bit切换约2850.838ms，板端往返约3016.871ms。此次修改没有更改硬件吞吐，也未从这些局部耗时推断端到端FPS。异构方法目前使用独立bit，频繁切换的开销是后续硬件整合的优化方向。
