# 手动输入、现场 FPGA 分割网页

本入口与之前的离线病例网页分开。旧网页、模型、已验收 bit/HWH、板端报告均不改动。
仍使用已验收的 cache-direct-return、100 MHz、21 节点 / 51 条命令的完整 INT8 U-Net。
没有重新训练，也不需要重新运行 Vivado。

## 实际计算流程

浏览器输入电脑上的 CT 路径 → 电脑读取原 HU / 量化 → 点击计算 → 板端常驻 FPGA 网络
→ 返回实际 head codes → 电脑 Sigmoid / 原尺寸恢复 / 人体约束 → 更新色块与 MPR。
整例全部计算完成后，再做原来的三维孤岛清理、体积统计和网格生成；连续局部片段计算完成后
也可以重建，但明确标记为局部，并跳过整肺孤岛清理。

- 加载 CT、拖动滑块、修改窗宽窗位不会自动运行模型。没有预先计算的分割结果。
- 可以只算当前轴位层、连续片段或整例。至少两层连续结果可以重建；不会把未计算层当成背景。
- 四宫格同屏：三维、轴位、冠状位、矢状位；点击剖面联动另外两面，紫色平面跟随轴位。
- 默认结果统一为“FPGA 肺区分割”（完整 FPGA 预测经电脑人体约束后显示），
  界面不再单独列出原始预测和人体约束两项。整例完成后仍可选择“三维清理后”；
  二维、三维及专家 Dice 使用同一个所选结果。原始输出继续保存用于核验。
- 可选加载专家标注，青色轮廓与橙色 FPGA 预测叠加，支持单独开关及同范围三维对照。
  只对实际已计算的层统计 Dice；没有标注时不显示 Dice。
- 单层原有实测网络约 0.686 秒；这不是 30 FPS 视频实时。新链路还包含通信与电脑预/后处理。
  240 层仅网络约 2 分 45 秒；新网页整例实际时间须上板测量，不能直接当成已验证速度。

## 输入格式和边界

### 专家标注对照

重启电脑网页后端并刷新页面即可使用；这项更新只涉及电脑端。

1. 默认勾选“加载专家标注”。对于包含 CT 和 RTSTRUCT 的单病例 DICOM 目录，
   “专家标注路径”留空会查找唯一匹配 CT Series UID 的 RTSTRUCT，例如 LCTSC 病例目录。
   若找不到，仍可正常加载 CT；若有多份匹配文件，须填写具体标注路径。
   本机已核对 `LCTSC-Train-S3-008` 的 `124-129` 层含实际肺轮廓，可用作小范围显示检查；
   该病例 `60-65` 层人工肺标注为空，没有青色轮廓是正常背景，不能人为补画。
   单独 CT 序列目录外的标注也须填写路径。RTSTRUCT 使用原有左右肺 ROI 名称识别、
   Frame / SOP / 轮廓平面核对和原栅格化规则，保留左右肺并集及重叠记录。
2. 也可填写人工肺标注 `.nii/.nii.gz`，或严格四键 `.npz`：
   `mask`（ZYX）、`spacing_zyx_mm`、`origin_lps_mm`、`orientation`（六方向余弦）。
   标签支持 0/1 或 0/1/2 左右肺并集，也接受二值 0/255；拒绝概率图及其他多分类标签。
   NIfTI 须声明 mm 单位。仅允许无损轴置换/翻转以及同一源 CT 的选层截取，
   方向、分辨率、位置或覆盖范围不符时拒绝加载，不插值、填洞或调整人工标签。
   几何匹配不能证明患者身份，操作者须选择该 CT 对应的真实人工肺区标注。
3. 如只看某一张 DICOM 且需 RTSTRUCT 对照，推荐填写包含完整序列和标注的病例目录，
   在“读取层”选单层；这样可核对所有轮廓的 SOP 关联，仅解码所选 CT 像素。
   部分 CT 加载时，标注栅格化会核对完整序列头和轮廓，再取对应片段。
4. 青色表示专家轮廓，橙色表示当前预测阶段，可分别隐藏。加载后、推理前也能查看
   三个二维剖面的专家标注，此时没有预测或 Dice。至少两层连续结果重建后，
   三维增加同范围的青色专家网格；局部对照不会画出片段以外的标注。
5. 状态栏分别显示当前阶段的“已计算范围 Dice”或“全部输入 Dice”；每个剖面另显示
   该剖面已计算像素的 Dice。零散补算按实际层汇总，不把未计算处作为背景。
   两者均空时显示 Dice 无定义；只有一方为空时 Dice 为 0。部分输入不称为全肺精度。

标注只用于展示和评价，不参与量化输入、FPGA 前向、人体约束、三维清理或阈值选择。
每个病例的 `input.json` 记录标注路径、文件/掩膜 SHA256 和几何，另存加载的
`expert_mask.npz`（含 basis_lps_zyx 的审计副本，不是四键导入格式）。
每次正常完成的计算另存 `*_comparison.json`，逐层 receipt 也记录实际输出与标注的
原始/人体约束后对照；重建报告包括所选范围的标注信息与各阶段指标。
不勾选“加载专家标注”则跳过标注读取。

### 只输入几层 / 只计算几层

重启电脑网页后端、刷新网页即可使用新增功能；板端服务、bit 和上传包都不用改。

1. **加载时就只输入部分层**：路径仍填 CT 目录或体文件，在“读取层”填写 `60-90`，
   只加载第 60 到 90 层（含两端，共 31 层）；也可填 `72` 仅输入一层。留空则加载全部。
   DICOM 会先扫描头文件确定空间顺序，只解码选中的像素数据。压缩 NIfTI / NPZ 的解压或轴重排
   仍可能访问整个文件，不能据此保证磁盘读取量按层数下降，但只保留选中片段用于分割。
2. **加载后只计算指定层**：“计算层号”支持 `0-9` 或 `0,5,10-15`，点击“计算指定层”。
   重复层号自动去重并按顺序计算；未选中的层不调用 FPGA，也不改已有结果。之后可以继续补算。
3. **直接输入单张**：路径可以填一个 `.dcm` 文件，加载后点“计算当前轴位层”，无需完整病例。

层号从 **0** 开始，区间包含末层。DICOM 按空间位置排序，不按文件名或 InstanceNumber。
NIfTI 使用轴重排后的标准轴位顺序。“读取层”指源数据排序后的层号；加载片段后，计算框与滑块
按这个片段从 0 重新编号，轴位下方及实际 FPGA 回执同时记录源层号。
例如读取源数据 `60-90` 后，计算 `0-4` 对应原来的 `60-64`。

为了保持真实层距，“读取层”只接受单层或连续范围；零散层请使用加载后的“计算指定层”。
只输入了一个片段，片段全部算完后会自动做**局部三维重建**，同时保留二维结果与局部 MPR。
完整 CT 中只计算一个连续范围（例如 `60-90`）也能局部重建，无需先计算其他层。
但不能把相隔多层的切片直接拼接成连续体，也不能把缺失层当作背景。
另外，“已提供的全部切片”不自动证明数据覆盖了完整肺脏，输入完整性仍需操作者确认。

### 局部三维的范围与限制

- 至少两层、真实层距、连续已计算结果才能重建。当前所有已计算层必须构成一个连续范围；
  有未补齐的间隔则暂不显示三维，可补算间隔或重新加载所需片段。
- 标题显示 `局部三维 · 源 60-90 层（上下截断）`。红色平面表示输入范围的两端；
  网格在体素外边缘封口只用于可视化，不代表肺的真实解剖边界，也没有补出缺失切片。
- 局部片段沿用人体约束后的原生掩膜，不套用整肺的三维孤岛清理规则，避免截断组织被误删；
  “三维清理后”选项仅供完整输入结果使用。网格构建不修改二维掩膜。
- 只显示“片段内分割体积”，不显示全肺体积；后台 `volume_ml` 保持空，局部统计单独记录为
  `region_volume_ml`，报告记录源层号、片段空间原点、截断说明和 `scope=partial`。
- 在完整输入中计算局部范围时，切换到范围之外的轴位层会隐藏三维中的当前层平面，
  不会让视图把未计算的区域纳入重建；范围内二维/三维保持联动。
- 单层只做二维分割，不沿厚度拉伸成假的三维器官。该更新只需重启电脑后端并刷新网页，
  不改板端、不换 bit，也不重训。

- 推荐完整单病例 DICOM 目录：按 DICOM 空间位置排序、RescaleSlope/Intercept 转 HU。
  目录有多个 CT Series 时会明确报错并列出 UID；缩小目录或在可选框指定 UID，不能悄悄选最大序列。
- `.nii` / `.nii.gz`：必须是原 CT HU，不是窗宽窗位后的显示灰度。勾选 HU/mm 确认；
  使用头文件坐标，无插值转为规范轴顺序；斜切 / 剪切网格拒绝导入，不能默默当成轴对齐。
- `.npz`：只接受 `hu`（ZYX）、`spacing_zyx_mm`、`origin_lps_mm`、`orientation`（DICOM 六方向余弦）
  四个键，需勾选 HU/mm 确认；不能夹带预存预测。
- 不支持 PNG/JPEG 当作 HU，也不支持缺层、非均匀层距、Enhanced 多帧 DICOM。
- 当前网页从**后端电脑的本地路径**读入，不是浏览器上传文件，也不是从开发板 SD 卡读 CT。
  因此电脑需要有 CT 源数据；路径不能填旧 `viewer.html` 或仅预测文件。
- 限制 128M 体素、每轴 <=2048，最小平面 16×16；单层可分割，但不会声称它是完整三维器官。

## 哪些计算在哪

| 位置 | 工作 |
| --- | --- |
| Z2 FPGA | 全部卷积、量化重缩放、池化、放大/拼接，完整网络前向 |
| Z2 ARM | 持久 CMA / MMIO 调度、输入输出同步、HTTP 服务 |
| 电脑 CPU | DICOM/NIfTI、原量化预处理、Sigmoid / 原尺寸恢复、人体约束、三维清理、网格 |
| 浏览器 | 交互、窗宽窗位、色块、MPR、三维显示 |

不是“所有医学处理都在 PL”，也不是“网页正在电脑跑 U-Net”。
显示的 FPGA 单层时间是板端持久运行时耗时；通信往返和完整任务耗时单独列出，不能混用。

## 安全范围

仅在可信的实验局域网使用。电脑服务只监听 127.0.0.1，并检查 Host / Origin / API token；
板端使用独立随机 token、禁止浏览器跨域，电脑不使用环境代理或跟随板端重定向。
HTTP 没有 TLS，不适合真实隐私病例、公网或多用户医疗服务；不要转发 8765/8088 到公网。
服务锁只防止另一份新服务抢占，无法阻止不合作的旧 Notebook 直接操作 PL；需要人为保证独占。
“层间停止”只在当前推理正常完成后生效；不会在 AXI 传输途中强行释放内存。
