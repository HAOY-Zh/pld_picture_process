## 输入与输出

输入是由冻结U-Net预测肺范围后得到的CT方形ROI，并保留5 mm余量。每次按物理间距采样中心前后 `[-2.5,-1.25,0,1.25,2.5] mm` 的五张平面，作为五通道送入YOLOv5n。二维卷积同时融合五层信息，检测头输出中心层上的二维候选框；整个CT按1.25 mm中心步长扫描，再将结果变换为物理坐标并在三维空间合并。

因此这是2.5D输入、二维检测、三维汇总，不是只读取单张切片，也不是三维卷积或逐体素结节分割。三维输出是候选中心和估计范围，不能冒充真实结节轮廓。

## 数据和标签

- 沿用冻结的247例训练病例、341个参考结节；与原CNN一致。
- 47例、56个参考结节仅在训练完成后用于整套CT开发评价和阈值分析。
- 18例开发检查、45例历史测试不混入训练；新的56例、90个参考结节继续封存。
- LUNA16的三维中心和直径可以转换为YOLO需要的二维框，无需更换数据集。但球形横截面只提供近似框，不是专家逐层轮廓；所有有交截的中心平面均生成标签。
- 无参考标准收录结节的训练病例仍保留。排除清单中的不确定发现投影到切片，并在目标存在性损失中忽略，避免一律当成健康背景。
- ROI仅由预测肺掩膜决定；不得根据专家位置移动或扩展ROI。另行记录参考中心覆盖率以暴露上游漏分。
- 目前仅证明扫描UID和原始像素去重，尚未证明患者级独立，也不是官方十折评价。

## 算法来源与适配

基于 [Ultralytics官方YOLOv5 v7.0](https://github.com/ultralytics/yolov5/tree/v7.0)，固定提交 `915bbf294bb74c859f0b41f1c23bc395014ea679`。保留官方主干、检测头、锚框匹配和CIoU损失，新增医学数据读取、排除区域损失掩膜、五通道初始化以及三维坐标输出。

配置为单类别、384×384输入，模型共1,766,422参数。使用官方COCO预训练YOLOv5n；输入卷积RGB权重按通道求和后除以5分配到五个通道，新的单类别头和小目标锚框单独初始化。此模型含SiLU、残差、6×6入口卷积和5×5池化等算子，不能认为现有板端加速器已经全部支持。

已有[肺结节研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC10611755/)采用五层输入YOLOv5生成候选、九视图ResNet-50抑制误报。本实验借鉴五层检测方向，**没有复现该论文的完整两阶段系统，也不能直接继承其指标**。

## 训练与评价协议

固定30轮、batch 8、AdamW、初始学习率0.0003、最终0.00001余弦衰减、首轮学习率预热。各例所有有正框的物理中心平面重复4次，另从肺范围Z网格固定随机抽32个平面；同一病例的数据只在内存中保留到该病例批次结束。使用XY直角旋转/镜像、Z通道反转，不使用RGB颜色增强或mosaic。混合精度训练，遇到非有限损失或梯度停止并记录错误。

保存每轮断点；最终使用第30轮EMA模型，不用校准结果挑选最佳轮次。每例完整CT推理后进行二维NMS和毫米空间三维合并，保留候选分数下限0.001，不设置Top-K。按相同的参考中心距离规则计算检出率、每套CT平均误报及CPM。必须与原5层、7层的开发结果并列，不能把切片mAP与整套CT的检出率混为一谈。

数据划分相同，但网络、初始化、标签、采样和更新数与原1.3万参数模型不同，属于系统方案对照，不是纯粹网络结构的单因素实验。

## 缓存与磁盘

不保存五份重复输入。每例只保存ROI缩放后的单通道原生Z平面，HU截断至[-1000,400]后编码为8位并压缩；读取时进行物理Z插值并组成五层输入。8位输入存储不代表网络已完成INT8量化。缓存不足3 GiB磁盘余量时停止，不继续填满磁盘。

本轮另清理了已经结束的上下文实验247个九通道训练数组，共6,853,786,496字节，约6.38 GiB。保留原始CT压缩包、五通道训练缓存、所有有效模型、元数据、病例输出、审计和测速结果。删除清单及保留文件哈希在 `data/project_cleanup_20261020/context_arrays.json`。历史九通道缓存如需恢复，可运行：

```powershell
.\.venv-lung\Scripts\python.exe python/lung_nodule_context_cache_restore.py
```

恢复会重新占用同样空间；本次不恢复。直接调用旧上下文训练入口会因缺失缓存而停止，应先恢复，不能重新生成或改写历史协议。

## 运行

代码：[YOLO入口](../python/lung_nodule_yolo.py)，可选依赖：[独立依赖表](../python/requirements-nodule-yolo.txt)。官方仓库位于本机被忽略的数据目录，团队复现时先克隆固定版本并下载官方权重：

```powershell
git clone --depth 1 --branch v7.0 https://github.com/ultralytics/yolov5.git data/third_party/yolov5_v7
Invoke-WebRequest https://github.com/ultralytics/yolov5/releases/download/v7.0/yolov5n.pt -OutFile data/third_party/yolov5_v7/yolov5n.pt
```

安装与本机Torch/CUDA匹配的torchvision后，再安装独立依赖。当前核验环境为Torch 2.8.0+cu126、torchvision 0.23.0+cu126，不要为了YOLO升级或替换已验证的Torch。

```powershell
.\.venv-lung\Scripts\python.exe -u python/lung_nodule_yolo.py run
```

`run`依次准备训练集、真实输入检查、训练、准备校准集、完整47例评价。后台任务已启动时不要重复运行；检查 `launch.json` 的进程和日志，确认退出后才恢复。预检权重只用于检查，全部丢弃，不计入正式训练。

重要状态文件：`plan.json`、`smoke.json`、`pipeline.json`、`preparation_train.json`、`training_progress.json`、`model_freeze.json`、`evaluation.json`。最初v1预检因NumPy标量JSON记录错误退出，未训练；修正后正式使用v2。

当前尚未完成INT8量化、RTL实现或PYNQ-Z2实测。记录的GPU阶段耗时不包含原始ZIP读取、U-Net或网页，不能当成整个平台端到端速度。FPGA是否有优势，需要进一步核对算子、特征图存储、DDR流量及实板结果。
