# 肺结节候选与 ROI、切片及三维联动交接要求

更新日期：2026-10-24。接收方：负责 ROI 的同学及其 Codex。

## 1. 这次需要完成什么

把肺结节检测产生的候选结果接到已有 ROI、MPR 和肺三维展示中，完成下面的操作流程：

**加载 CT → 完成整例肺分割 → 点击肺结节检测 → 显示候选列表 → 选择候选 → 自动定位切片、框选 ROI，并在肺三维图中高亮同一个候选。**

最终希望看到的是：列表、轴位切片、冠状位、矢状位、局部 ROI 和肺三维图，都能围绕同一个候选位置联动。用户不用手动寻找切片和重新画框。

这里显示的是“肺结节可疑候选区域”。当前模型给出中心和大小估计，没有输出结节逐体素轮廓；自动 ROI 和三维包围框不能标成“结节精确分割”。

## 3. 分工边界

| 工作 | 负责人 |
|---|---|
| 结节检测模型、采样、量化、FPGA 推理及候选合并/评分 | 肺结节模块负责人，即发起此次交接的一方 |
| 整病例检测结果的生产与候选数据接口 | 肺结节模块负责人，与整机集成人对接 |
| 根据候选自动设置 ROI，完成列表、切片、MPR、三维之间的定位与选择 | ROI 同学，本次主任务 |
| 将联动组件合入统一网页、协调服务请求与其他模块 | ROI 同学与整机集成人配合 |
| 统一管理 bit、时钟、CMA、任务排队及硬件异常 | 整机集成人；页面组件不直接控制 Overlay |

ROI 同学不需要重新训练模型、重写检测算法、改变候选筛选阈值，或另建一套 FPGA 服务。接口尚未接通时，先按本文件的数据约定开发联动；通过适配层接收真实结果，避免把页面绑定到测速脚本或私有目录。

## 4. 候选数据约定

一次检测结果对应当前 CT 病例和当前结果版本。页面至少绑定 `case_id`、`result_id` 与候选列表；同一候选在各个视图中使用同一个 `candidate_id`。

候选字段沿用现有检测代码的命名：

| 字段 | 含义与注意事项 |
|---|---|
| `candidate_id` | 本次结果内的候选编号；跨病例或跨结果不能单独用它识别候选 |
| `center_index_zyx` | 原始输入 CT 体素索引中的三维中心，顺序为 `[z,y,x]`，可以是小数 |
| `bbox_zyx` | 原始输入 CT 中的包围框，顺序为 `[z0,z1,y0,y1,x0,x1]`，上界不包含端点 |
| `center_lps_xyz_mm` | LPS 世界坐标中的中心，顺序为 `[x,y,z]`，单位 mm |
| `estimated_scale_diameter_mm` | 模型估计的大小，单位 mm，不是专家量取的真实直径 |
| `score` | 最终候选评分；展示其原值，不改变阈值、不解释成恶性概率 |
| `score_kind` | 评分含义说明；最终跨层评分与原始 CNN 分数可能不同 |
| `raw_score` | 若检测结果提供，表示跨层评分前的原始 CNN 分数；不能覆盖最终 `score` |
| `region_kind` | 当前为中心和大小估计形成的区域，不是逐体素病灶分割 |

下面仅是接口示意，不是真实检测结果，不用于演示医学效果。真实几何从当前已加载 CT 取得，不根据示意数值重新生成：

```json
{
  "schema": "ct_nodule_prediction_v1",
  "case_id": "example_case",
  "result_id": "example_result",
  "candidate_count": 1,
  "candidates": [
    {
      "candidate_id": "cnn_00001",
      "center_index_zyx": [60.0, 220.0, 310.0],
      "bbox_zyx": [56, 65, 215, 226, 305, 316],
      "center_lps_xyz_mm": [48.0, -24.0, -25.0],
      "estimated_scale_diameter_mm": 8.0,
      "score": 0.82,
      "score_kind": "frozen_cross_layer_score_not_malignancy_probability",
      "region_kind": "predicted_center_and_size_not_voxel_segmentation"
    }
  ]
}
```

页面消费的是合并、评分之后的三维候选，不把同一候选在相邻层的多个框当成多个结节。HTTP 路由、异步任务状态和结果获取方式由双方结合现有服务冻结，本文件不将一个尚未实现的新接口写成已经可调用。

## 5. 具体交互要求

### 5.1 候选列表

检测完成后展示候选编号、估计直径和候选分数。按服务给出的结果排序显示，编号和坐标保持不变。

点击一项后，将其设为唯一的当前选中候选，并同步更新 ROI、切片、MPR 和三维高亮。候选较多时，先保持全部候选结果完整；分页或隐藏标记只影响显示，不能悄悄删掉检测结果。

### 5.2 自动 ROI 与局部放大

根据选中候选的 `bbox_zyx` 自动设置 ROI，复用已有 ROI 展示和处理接口。默认展示候选中心附近的切片及局部原 CT 放大图；可按已有窗宽窗位观察。

如需要扩大 ROI 留出观察边界，应另外计算“显示/裁剪用 ROI”，记录扩展量，并保留检测给出的原始框。扩展后须裁剪到 CT 边界。不要直接修改候选中心、大小、分数或原始包围框。

如果复用已有 HU 筛选、掩膜或计数，仍按其已有接口和实际后端执行。ROI 框内体积、阈值体素体积不能标成真实结节体积。

### 5.3 轴位及相邻切片

选中候选后，轴位视图跳到最接近其中心 Z 索引的原始切片。显示层号时沿用当前网页从 0 或从 1 开始的习惯，在接口处明确转换，不能多偏移一层。

对位于 `[z0,z1)` 范围内的轴位切片显示该三维包围框的截面；范围以外不画这个候选框。当前只是包围框截面，相邻层可以具有相同矩形，不能伪装成逐层变化的结节轮廓。

翻页、拖动滑块和切换窗宽窗位只更新显示，不重复检测。

### 5.4 MPR 三个切面

选中候选后，将轴位、冠状位、矢状位的观察位置同步到同一个三维中心，并显示定位线、中心标记或框截面。

MPR 上的框应按三维包围框与当前切面的相交关系生成。不要将轴位的同一个二维矩形直接复制到另外两个方向。

### 5.5 肺三维图

在已有肺表面上叠加候选中心标记或三维线框。选中候选明显高亮，其他候选仍可辨认；支持显示/隐藏全部候选标记。

点击列表候选，三维标记同步选中；点击三维候选，反向选中列表并更新切片、MPR 和 ROI。三维交互使用 `candidate_id` 回查候选，不根据屏幕距离猜测对应项。

优先实现中心标记与包围框。球体如用于显示，须标明是估计大小的示意，不能当成真实结节重建。无需等待结节精确轮廓分割。

## 6. 坐标与状态必须保持一致

1. **统一使用原 CT 几何。** 数据来自原始体数据索引及其 origin、spacing、方向基。网络 patch、lowering 或画布中的局部坐标不能直接绘到原 CT。
2. **沿用现有三维坐标变换。** 如果肺表面显示前做了坐标轴交换、镜像或中心化，候选执行相同变换。LPS、RAS 与浏览器显示坐标之间不能混用。
3. **半开区间保持一致。** 例如轴位第 `z` 层的判定为 `z0 <= z < z1`；裁剪使用 `volume[z0:z1,y0:y1,x0:x1]`。
4. **不交换左右或混淆单位。** ZYX 索引与 XYZ 毫米坐标是不同字段。不能用毫米数直接当数组索引，也不能只乘 spacing 而忽略方向和 origin。
5. **旧结果及时失效。** 换病例、重新分割或重新检测时清除旧候选选择、自动 ROI 和三维标记。迟到的旧请求也必须通过 `case_id`、`result_id` 检查后才能显示。
6. **没有候选也能正常结束。** 空结果明确显示“未检出满足当前条件的候选”，清除旧标记，不保留上一病例的框，也不解释成确定没有结节。
7. **显示与计算分开。** 点击列表、旋转三维图、翻切片、切换窗宽窗位，不调用 U-Net、结节 CNN 或重新下载 bit；若用户主动执行已有 ROI 处理，再按其原流程提交任务。

## 7. 建议推进顺序

第一步完成“候选列表 → 中心切片定位 → 自动 ROI → 局部放大”。这一步先确认病例身份、索引和框范围正确。

第二步接上 MPR 三切面定位、相邻切片框显示和病例切换清理。

第三步增加肺三维候选标记与双向选择，最后由整机集成人合入统一服务和网页，接真实整病例候选结果。

开发时允许使用明确标为测试的示例候选验证界面；最终演示和效果截图应来自真实检测结果，不能用人工放置的示例框冒充检出结果。

## 8. 完成后的验收与交付

| 场景 | 应达到的效果 |
|---|---|
| 选择一个真实候选 | 列表、ROI、三个切面与三维标记均指向同一位置 |
| 点击三维候选 | 正确反选列表并定位切片，候选编号不变 |
| 观察相邻层 | 在框覆盖的层范围显示截面，范围外不显示 |
| 各向异性或非默认方向的 CT | 定位仍正确，没有左右翻转、尺度拉伸或 Z 轴偏移 |
| 靠近 CT 边界的候选 | ROI 合法裁剪，无负索引回绕或越界 |
| 快速切换候选或病例 | 无旧请求覆盖新选择，无上一病例候选残留 |
| 空结果 | 正常提示并清空旧标记 |
| 单纯浏览和定位 | 不增加网络推理、硬件任务或 bit 下载次数 |

交付时提供：修改的源码与提交位置、候选结果接入函数/接口说明、一份测试用候选示例，以及真实结果联调截图或录屏。测试中使用的模拟数据和模拟后端要明确注明。

如有接口缺项，列出缺少的字段或调用能力，由肺结节模块负责人补齐；不通过复制专家标注、硬编码病例坐标或改变模型阈值来替代真实结果接入。
