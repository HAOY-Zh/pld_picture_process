## 按 8 通道块进行结构化剪枝

用户接受平均 Dice 最多下降 **1 个百分点**，前提是有明显提速。此值是 Dice 绝对差 0.01，
不是相对下降 1%。候选全部保留原 256×256 输入、预处理、sigmoid 后原生双线性插值及阈值 0.5，
使用相同 CT-only 身体约束与原三维清理，不为候选调整后处理。

`python/lung_prune.py` 沿编码器、解码器及 skip 拼接传播原始通道索引，按 BN 折叠后卷积核 L1 排序。
移除完整 8 通道块，使 HWC8 工作量与真实命令数下降。只把权重置零不会减少现有稠密硬件的计算量。

18 个原训练病例用于微调与量化校准，6 个原开发验证病例用于选择与复核。
没有使用 LCTSC Test 或 COVID 病例调参；该结果属于开发验证，不是新的独立泛化证据。
FP32、真实 CPU INT8 和硬件 Q31 定点整网分别评价，参考标签保持原生分辨率不变。

2. **INT8量化**：固定浮点检查点与模型结构，比较FP32与该模型量化后的精度、权重/激活存储和ARM实测速率。
   原模型同板CPU为1547.211→908.312 ms；软件测速同时受所用FP32/INT8内核实现影响，不能声称全部收益只由位宽决定。
   不用“FP32 CPU→INT8 PL”单独证明量化收益，因为执行平台也变了。
3. **结构化剪枝及恢复训练方案**：分别在CPU INT8和同一PL bit上比较原模型与剪枝候选，同时展示FP32/INT8精度变化、
   参数量、有效MAC、HWC8填充后工作量和命令数。早期balanced的CPU/PL时延分别减少23.27%/21.69%；本轮fisher_moderate为12.48%/10.90%。
   当前结果包含剪枝后恢复训练与量化校准，不能称为删除通道本身使Dice提高；如需分离恢复作用，再展示恢复前后的验证结果。
4. **PL编程与架构优化**：固定原模型、量化和时钟，按已有保留版本比较缓存/响应路径、flow响应直通及池化缓存、精确拼接查表。
   缓存直返版686.368 ms→flow 569.419 ms→精确查表553.081 ms均已有独立实板验收；本轮原模型查表复测为552.647 ms。每步报告整网壁钟、算子周期和资源。
   若两个优化一起启用，只能把该实板差值归于组合；要宣称各自独立贡献，需单独开关的实测，或明确标为局部仿真消融。
5. **最终组合收益**：最终模型与最终bit实际组合后重新核验和测速，再与原始FP32 CPU报告系统综合收益，
   同时保留第1项的同模型硬件加速比。不能把剪枝与硬件优化的独立比例直接相乘代替实测。

### 测量与写作口径

- CPU使用同板ARM，固定核心数、实际频率、优化编译选项、库与线程设置，保留优化软件基线；工作站GPU不作为同板CPU对照。
- 同一对比使用相同CT输入、256×256分辨率、预后处理与计时边界。明确一次性编译/bit下载/分配、输入输出同步和主机调度哪些计入。
  单独列引擎活动时间、包含主机开销的网络推理时间、包含读片/预后处理/三维重构的系统时间，避免混用FPS。
- 最终需补代表性多切片/连续运行测量，报告样本量、预热、均值、中位数、P95和波动；不把当前单切片重复测速包装成病例级结果。
- 每组保存权重/量化参数/输入/bit/源码哈希、实际CPU/PL频率、逐次计时、节点周期、真实输出和独立核验结果。
  新轮次使用新结果目录，保留历史记录，说明跨轮次环境波动。
- 资源报告LUT、FF、DSP、BRAM、实际频率和时序；剪枝复用同一bit时不宣称物理DSP/BRAM减少，
  其收益是工作量、存储/搬运需求与时延下降。112→80 DSP属于查表硬件改进。
  DDR流量、带宽、功耗或能效若尚无计数器/测量证据，须注明估算或待测，不能从MAC减少直接推导。
- 若主张“本剪枝策略优于普通剪枝”，还需明确普通剪枝基线和可比的压缩预算；现有证据支持硬件对齐结构化剪枝有效，
  尚不能声称它优于所有其他剪枝方法。失败候选、单病例退化和精度/速度取舍也应保留。

后续顺序：先单测原模型查表bit，再按需要补剪枝FP32同板基线与最终组合，最后补多切片持续运行。
本节记录实验及报告要求，不表示这些待测项已完成，也不授权自动替换在线服务。
