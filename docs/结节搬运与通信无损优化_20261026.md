# 结节搬运与通信无损优化：实板验收（2026-10-26）

后续默认版本已更新为 DualExact 修复版，见[肺分割与结节检测无损调度优化](肺分割与结节检测无损调度优化_20261026.md)。下文保留 Compact V2 的验收记录和当时部署信息；不同病例的耗时不能直接比较。

**已部署到正式网页8099。同一351层病例的完整结节检测从209.78秒降至116.57秒，约1.80倍，耗时减少44.43%。全部281张完整检测头哈希、5,911个原始候选及最终8个候选完全一致。**

对照的是相同CT、相同已完成的肺掩膜、同一个模型、100 MHz bit、INT8规则、整层计划、解码/三维合并和冻结跨层评分阈值。两次均包含最终评分筛选。
计时不包含先前肺分割、首次编译/服务启动自检、病例读取/恢复和浏览器绘图。两次为分开运行的同病例测量，不是全数据集平均或CPU/FPGA加速比。

## 发现的瓶颈

上一版209.78秒中：网络调用累计108.91秒，输入排列和缓存同步累计62.38秒，实际PL活动累计36.95秒。
原传输在电脑先把五张量化图展开为45通道，板端再用NumPy转换到HWC8输入缓冲，存在重复数据和大块临时复制。

## 改动

1. 传输原五张UINT8量化图，而不是45通道展开图。HU插值、取整、窗口及量化仍在原位置按原公式执行。
2. 板端使用小型本地编译C++函数，把原stride-two展开和HWC8排列融合，直接写入原CMA输入缓冲，保持原缓存flush。
3. 所有卷积、池化、拼接的PL调度、配置、权重装载、完成计数、超时、同步和全部保护区检查保持原逻辑。AST对照确认除了输入上传契约和函数名，调度方法不变。
4. 输入仍用无损zlib压缩；完整检测头改用二进制封装回传，保留有长度上限的JSON回执和完整head哈希，省去Base64封装。
5. 同一实例复用HTTP连接并禁用Nagle等待；仍串行提交。故障不自动重试，不使用CPU卷积回退，不并发操作FPGA。
6. 新增 `/v2/shared/nodule-canvas`，旧完整45通道接口仍保留，便于同服务同bit直接对照。

没有修改模型/权重、bit、时钟、采样位置、搜索范围、输出裁剪、候选上限、最终阈值或任何参考标注；没有通过减少搜索范围或丢弃候选来加速。

## 实测分解

| 范围 | 上一版 | 本版 |
|---|---:|---:|
| 完整网页检测任务 | 209.78 s | **116.57 s** |
| 实际PL活动累计 | 36.95 s | 36.95 s |
| 常驻网络调用累计 | 108.91 s | **53.60 s** |
| 输入排列、复制与缓存同步累计 | 62.38 s | **7.08 s** |
| 整层请求往返累计 | 200.81 s | **106.09 s** |
| 冻结评分累计 | 1.71 s | 1.49 s |

| 压缩后输入总量，十进制MB | 423.39 MB | **184.13 MB** |

计时项有包含关系，不能相加。实际PL活动几乎不变，体现本轮收益来自搬运和通信。
未压缩输入减少55.56%，压缩输入减少约56.51%。评分耗时等小幅变化包含运行波动，不能归为本轮算法优化。
新响应总计约28.15 MB；旧响应没有按相同口径记录字节数，因此不虚构回传字节减少比例。

- 原生打包测试覆盖随机、全0、全255、不同矩形和边界：与原`lower_canvas`再`feature_words`所得每个字节一致，填充通道正确，尾部保护区不变，原输入未改写。
- 本地二进制协议边界/截断检查、HTTP连接复用、故障保留及不重试检查通过。
- 软件完整整数参考的输入、解码、原始/评分后候选对照通过；明确作为软件测试，不冒充实板性能。
- 新服务实际启动自检：128×128和256×320的完整head与旧接口逐值一致，实际CMA输入字与原Python布局逐值一致。
- 三个真实CT平面、每个两次新请求，与旧接口完整head逐值一致。
- 正式网页整例：281个完整head哈希逐一相同，所有原始候选与跨层分数严格相同，最终8个候选严格相同。
- 正式网页候选和局部MIP接口检查通过；原351层肺分割和三维结果保留。

此病例没有专家标注，本轮不新增检出率或Dice结论。8个候选不等于8个真结节，旧模型已有的漏检/误检不会因数值完全一致的搬运优化而改善。
