# 肺结节流程耗时诊断：CNN与CPU外围处理

2026-10-22，针对“两个轻量CNN为什么整套耗时差很多”的问题，在113例已完成、现已暴露的测试病例中，按历史整套耗时选取中位病例和75%分位病例，仅增加计时。没有训练、改算法、改阈值或重新评价113例精度。

**两个病例的肺掩膜、候选中心及分数均与已冻结测试产物核对通过。主要时间消耗在CPU上的人体包围范围、搜索掩膜、采样和解码；本次结节CNN的GPU前向分别约1.25秒和1.21秒，不是50秒。**

## 先核对版本和计时范围

- 旧S3-008病例为240张切片。历史0.795秒是已准备输入上的原始U-Net预测，另计4.492秒生成专家和预测两套三维表面，不含完整原始读片、人体范围约束、导出或浏览器显示。
- 当时U-Net是122,321参数，并非一万出头。此次结节实验也使用该冻结原始U-Net生成肺范围；网页、剪枝、板端记录应分别识别版本。
- 当前结节CNN为13,157参数，输入5×128×128，单图块约19,038,208次卷积MAC。113例平均每套CT实际处理约4,711个图块，图块含重叠边缘。
- 113例整套流程平均52.66秒、中位47.72秒，包含ZIP读取、重新肺预测及约束、搜索和采样、CNN、合并、跨层证据评分及结果输出；不含三维网格生成和网页渲染。

所以旧5.29秒的两个计时项和新52.66秒不是同一计时范围，不能解释成“结节小CNN比肺U-Net慢十倍”。

## 本次两例诊断数据

病例A：245张切片，3,884个结节图块；病例B：298张切片，3,737个图块。

| 环节 | 病例A：秒 | 病例B：秒 |
|---|---:|---:|
| ZIP读取、解压及像素/几何身份核验 | 2.68 | 3.89 |
| 肺预测及外围处理合计 | 30.89 | 50.09 |
| 其中：人体包围范围约束，CPU | 24.67 | 42.00 |
| 其中：肺输入尺寸变换，CPU | 2.85 | 3.21 |
| 其中：U-Net GPU前向 | 2.32 | 3.53 |
| 结节候选流程合计 | 53.87 | 50.80 |
| 其中：肺区搜索掩膜填充及扩展，CPU | 16.51 | 20.92 |
| 其中：图块调度，CPU | 1.32 | 0.54 |
| 其中：图块重采样，CPU | 16.08 | 15.00 |
| 其中：输出解码，CPU | 9.84 | 6.71 |
| 其中：候选合并，CPU | 1.23 | 0.86 |
| 其中：跨层局部特征，CPU | 4.46 | 2.89 |
| 其中：结节CNN GPU前向 | **1.25** | **1.21** |
| 局部特征生成后的跨层打分 | 0.0053 | 0.0044 |

“其中”各项嵌套于合计，不要与合计重复相加。GPU前向由CUDA events测量，不包括完整H2D/D2H；合计还包含传输、张量准备、插值、分配及未单独拆分的调度开销。

**本次诊断不是上一轮52.66秒均值的精确拆分。** 这两例此次计时范围合计约87.45秒和104.79秒，而各自在上一轮的完整记录为47.72秒和67.33秒。运行时机器状态未控制，增加了计时包装及CUDA events，并先进行了模型预热；本次还排除了结果序列化和输出。因此应将其用于识别主要耗时函数，不能作为可靠前后加速比、全113例阶段平均值或稳定吞吐基准。

## 参数少为什么仍有很多处理任务

参数量表示模型中可学习权重的数量，不能代表整套流程需要搬运和处理多少像素。肺网络逐张处理准备好的256×256图像；结节算法需要保留小目标细节，按0.8mm面内网格、1.25mm深度步长生成五层上下文和大量重叠图块，再把响应合成三维候选。

但也不能简单把这次慢归咎于图块使卷积计算更多。本次实际统计：

| 卷积MAC范围 | 病例A | 病例B |
|---|---:|---:|
| 肺U-Net整套CT | 163.13G | 198.42G |
| 结节CNN整套CT | 73.94G | 71.15G |

结节卷积工作量反而更低，当前GPU前向也更短。CPU重复形态学处理、重采样、内存访问与解码才是应优先检查的实现开销。

## 后续优化重点

1. 在统一系统中复用已经完成的肺分割与几何信息，避免结节模块重复运行U-Net和人体包围范围。注意原始、剪枝INT8、FPGA肺掩膜并非天然逐像素相同，切换来源需明确版本并验证候选结果。
2. 优化CPU人体范围与肺区搜索掩膜的形态学、填充和内存操作，先保证输出一致。现有基础处理3×3方核不等价于这里按物理尺寸构造的核，不能直接替换后宣称算法没变。
3. 复用规则网格和相邻切片采样结果，降低重叠图块的重复插值、复制及解码开销；这是后续流式/缓存硬件设计的合适对象。
4. 独立做受控端到端测速，再决定是否值得进一步压缩CNN。当前证据不支持把“继续减少参数”作为首要提速措施。

上述仅为诊断与下一步方向，尚未实现这些优化，没有新的加速比、FPGA速度或精度结论。
