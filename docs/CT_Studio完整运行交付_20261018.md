## 4. 单一所有者、查询、停止和恢复

板端端口 8765；电脑网页默认 127.0.0.1:8090。独占锁 `/tmp/lung_live_z2.lock`，服务在同一进程内串行管理基础处理与分割 Overlay、时钟、DMA/CMA。HTTP 忙碌请求拒绝，不并发执行硬件。输出复制后返回，下一次 DMA 不覆盖已返回数组。FPGA 失败显示失败，不静默回退电脑参考。

主机只读健康查询（不会重载 bit 或触发计算）：

```python
# 在电脑项目根目录，用已安装的 Python 运行；不要打印 token。
import sys, json
from pathlib import Path
sys.path.insert(0, 'python')
from ct_platform_client import PlatformClient
p = Path('data/ct_platform_20261017_v2/host_config.json')  # fast 时换成 fast 路径
c = json.loads(p.read_text(encoding='utf-8'))
t = (p.parent / c['token_file']).read_text(encoding='utf-8').strip()
m = json.loads((p.parent / c['platform_manifest']).read_text(encoding='utf-8'))
client = PlatformClient(c['board_url'], t, m)
identity = client.health()  # 验证身份，并要求 ready、非 busy
print(identity['platform']['ready'], identity['platform']['busy'], identity['platform']['active_operation'])
```

停止电脑网页用 Ctrl+C。健康空闲的板端服务在持有它的原内核运行：

```python
from ct_platform_fast_service import stop_idle_platform_service
stop_idle_platform_service(platform_service)
```

该停止辅助函数也可用于原版本服务，但需先部署包含它的 fast 目录，并从该目录导入。它检查请求锁、故障状态及硬件空闲后才交还资源；失败时不要强制释放 CMA、下载新 bit、删锁或自动重试。后续恢复由唯一集成负责人依据完整故障记录执行。正常停止后再次启动可保留此前生成的回执；新回执使用 UUID 不覆盖历史输出。

## 6. 硬件接口与构建源码

除了原 `python/`、`pynq/`、`fpga/`、`matlab/`，新增 `hardware/ct_studio_20261018/`：

- `segmentation/rtl/`：从实际已实现 IP 导出的对应 RTL，包含缓存/窗口和张量引擎版本，逐文件匹配历史实现证明；不依赖原电脑 data 中的隐藏覆盖文件。
- `segmentation/build.tcl` 与 `ps_settings.tcl`、XDC、复位检查 Tcl：移除作者绝对路径的独立构建入口。
- `basic_shared/rtl/`、`build.tcl`、`ps_settings.tcl`：共享基础 bit 的完整 RTL 与构建配置。
- `source_manifest.json`：快照哈希与版本关系。旧六独立基础项目的源配置和 Verilog 继续保留在 `fpga/pynq_z2_*_axis/` 及 `fpga/`；直接使用交付 bit 不需要先构建 Vivado。

Vivado 2022.2、器件 xc7z020clg400-1；在仓库根目录、Vivado 环境执行：

```text
vivado -mode batch -source hardware/ct_studio_20261018/segmentation/build.tcl -tclargs data/rebuild_segmentation build
vivado -mode batch -source hardware/ct_studio_20261018/basic_shared/build.tcl -tclargs data/rebuild_basic_shared
```

输出必须是当前仓库 data 下的新目录。便携 Tcl 仅调整路径，本轮未重新跑实现，首次集成使用已附原 bit；重建 bit 哈希通常会变化，必须建立新清单并独立验收，不能修改旧清单冒充原验收版本。

| 模块 | IP / 缓冲与接口 |
| --- | --- |
| 共享基础 PL | `axi_dma_0`，32-bit AXIS、64-bit DDR，非 SG；512×512；每向传输 1,048,576 字节。两个 uint32 CMA 缓冲各 262144+16 words，后 16 words 是越界哨兵 |
| 基础参数 | `axi_gpio_0` 双 32-bit 参数通道，`axi_gpio_1` 3-bit 模式；六种模式编号 0..5，对应 window/threshold/erosion/dilation/opening/closing；参数编码见固定服务和 RTL |
| 原六 bit | `axi_dma_0`；窗口 GPIO 双 16-bit WL/WW；阈值 GPIO 打包上下界；形态学数据为二值；具体地址由对应 HWH/PYNQ 描述提供 |
| 分割 | `lung_conv8_axil_0` @0x43c00000，`lung_tensor_axil_0` @0x43c10000；GP0 控制，HP0 64-bit 访问 DDR。输入 1×256×256 uint8，输出同形状 codes，内部 HWC8 缓冲按冻结网络计划分配；量化、寄存器与状态定义见 `lung_axil.py`、`lung_tensor.py`、`lung_fast.py` |

共享基础 bit 目标/实现时序 100 MHz，分割服务逐次核对实际 100 MHz；原基础 bit 的实际 FCLK0 在每次回执记录，不能把目标频率当作新的上板测量。跨基础/分割仍会重配置；六种共享基础方法之间无需换 bit。模型初始化、自检、切换、DMA、服务和网络往返分别计时，禁止将单核时间称为整例时间。
