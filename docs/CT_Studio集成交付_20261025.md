# CT Studio 集成交付

本分支保存当前网页、ROI 硬件统计、结节候选联动及批量调度的集成代码。保留现有轻量 CNN、原肺分割模型、基础处理和各自匹配的 bit/HWH；不覆盖队友分支。

## 已集成内容

- 原始或增强 HU 的病例来源管理，CT 导入、基础处理及轻量 CNN 去噪。
- 真实 FPGA 肺分割、MPR 三切面和三维重建。
- 整病例结节 CNN 实验检测、候选列表、三维反选和自动 ROI。
- 手动 ROI、跨层 HU 统计、局部 MIP、记录及导出。
- 最多 8 块批量传输、提前采样、状态统计缓存和安全取消。

同一真实病例的检测耗时从 696.98 秒降至 431.29 秒，减少 38.12%。全部 5237 个图像块的输入和实际 FPGA 输出、8288 个候选及 21 层自动 ROI 统计一致。这里证明工程流程与数值一致性；分数仍是未校准的 CNN 实验分数。精简验证记录见 `evidence/ct_studio_integration_20261025/verification.json`。

## 必要运行资产

`runtime/ct_studio_integration_20261025/` 中的 ZIP 包含匹配硬件文件、整数权重、驱动和合成自检。它不包含本机令牌、真实患者图像、训练检查点或实验临时文件。安装时为接收方单独生成连接令牌，并重新绑定嵌套文件清单；原运行目录不会被覆盖。

发布副本保持模型、权重、bit/HWH 不变，历史病例自检图替换为固定合成图。新合成自检已完成电脑整数参考核验，接收端启动仍需实际通过板端自检。源共享引擎来自同仓库提交 `95e570f260a2dc657956a174db11084565c8a4ff`，保留了独立命名空间和来源信息。

## 在新目录安装

使用 Python 3.11，在本分支根目录执行：

```powershell
py -3.11 -m venv .venv-web
.\.venv-web\Scripts\python.exe -m pip install -r python/requirements-web-fpga.txt
.\.venv-web\Scripts\python.exe -B -X utf8 python/ct_studio_integration_release.py install --board-url http://192.168.2.99:8766
.\.venv-web\Scripts\python.exe -B -X utf8 python/ct_studio_integration_release.py verify
```

安装产生 `data/ct_studio_integration_20261025/`。其中 `ct_studio/` 是板端包，`host_config.json`、`host_platform.json`、`shared_host_platform.json` 是与该板端包配对的电脑配置；令牌仅在本地生成，不提交 Git。

板端包需要放入 PYNQ 的独立目录，使用现有 PYNQ Python 环境运行 `ct_studio_shared_owner.py`。其 `--folder` 指向该目录，`--expected-manifest` 使用电脑端 `installation.json` 输出的 `service_bundle_sha256`，端口为 8766。首次启动执行真实硬件自检，成功后才提供服务。

已有硬件服务时，必须等它空闲并正常交还硬件后再启动新所有者，不能同时运行两个硬件控制进程。新安装生成的凭据和清单不等于原服务的凭据和清单，电脑与板端必须使用同一安装包的配对文件。安装命令本身不连接、不重启开发板。

板端就绪后运行：

```powershell
.\start_ct_studio_integrated.cmd
```

浏览器地址为 `http://127.0.0.1:8099/`。无板卡浏览仍可使用 `start_ct_studio_pc.cmd`；该模式不执行 FPGA 神经网络推理。
