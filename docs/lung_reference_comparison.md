2026-10-12 已完成。本次不训练、不替换原模型、不修改人工标注、不改 FPGA。
目标是回答两个问题：成熟公开模型能否减少已发现的内部漏分；真实边界和错误边界的 HU 变化是否不同。

## HU 分析：边界两侧变化，而不是单个 HU 阈值

HU 来自外部无损原始 HU 缓存或重新读取的 DICOM RescaleSlope/Intercept，
不是窗口显示灰度或放大的 256 输入。外部缓存几何/哈希校验保持原样；
DICOM 复用原患者、Frame、文件物理顺序、形状和间距检查。
两例实际 ImageOrientationPatient 均为 [1,0,0,0,1,0]，确认是这里假定的轴向 LPS 输入。

采样方法：

1. 人工外边界：只取外轮廓，排除人工掩膜合法封闭孔洞的边界。
2. 错误内部边界：原预测前景边缘邻接 FN、边缘点在人工肺内至少 2mm。
3. 法向由平滑的掩膜有符号距离求得，不按 HU 梯度选择边缘，避免只挑强边缘。
4. 按原始物理像素间距，在法向 -3/-2/-1/0/+1/+2/+3mm 双线性读取原 HU。
   0 是离散前景边缘像素，不是精确亚像素表面，因此曲线只是近似诊断。
5. 错误内部组要求 **七个采样位置的插值邻域全部位于原人工肺掩膜内**，
   防止内部曲线跨到真正肺外；每组最多 512 个按空间顺序均匀选点，不按 HU 或效果选点。
6. 两侧平均 HU 差 = (+1/+2/+3mm 平均) - (-1/-2/-3mm 平均)。
   为方便比较正反变化，表格取每个采样点差的绝对值，再求中位数。

| 病例 | 人工外边界绝对 HU 差中位数 | 错误内部边界绝对 HU 差中位数 | 内部组有效采样数 |
| --- | ---: | ---: | ---: |
| coronacases_003 | 728.46 | 409.30 | 512（1333 个符合条件点中系统选取） |
| coronacases_009 | 803.33 | 583.64 | 512（627 个符合条件点中系统选取） |
| S2-006 | 403.54 | 213.00 | 83 |
| S3-008 | 597.68 | 137.05 | 325 |

你的观察在这些切片上有数值依据：外边界的 HU 过渡整体较强，内部误边界往往较弱或变化形态不同。
但两类分布有重叠，不构成可靠的固定 HU 阈值，也没有证明它能在其他病例自动区分边界。
S3-008 的人工与内部错误边缘点 HU 中位数恰好都约 -395，说明仅看边缘点亮度不够；
在这里两侧的变化比该单点数值更有辨别线索。
采样点相互相关、所在解剖部位不同、法向近似且只看四张图，不作统计显著性或普适性结论。

### 采样复核与历史保留

初始 `r231_hu_comparison/` 中的内部点中心满足 2mm 条件，但三毫米采样线可能伸到肺外。
复核发现初始选取内部曲线中跨界路径数分别为 39/512、24/512、221/304、135/460。
因此追加上述“整个插值采样路径在人工肺内”条件。
直接复用已有 `slice_masks.npz`，不重新执行 R231，输出新目录 `r231_hu_guarded_profiles/`。
初始报告/图片没有覆盖；最终 HU 解读只使用 guarded 版本。
新协议分别记录历史推理源码哈希、当前分析源码哈希及来源报告哈希，四张分割指标未变。
修正前后都留痕，不把两套 HU 数据混用。

## FPGA 与下一步边界

R231 注册参数 31,054,275，原小模型 122,321，约 254 倍；不能据本机 GPU 成绩承诺 PYNQ-Z2 部署。
本次仅把它作为电脑端参照，没有板端 AI 推理、资源综合、INT8 转换或新比特流。

建议后续先从训练病例的覆盖、有效输入视野及边界学习入手，保留未修改人工标签。
参考模型可以提供训练期指导，但不能将其全输出当作真值，因为当前也有漏分、多分及目标定义差异。
如果使用蒸馏，只能从 TRAIN 病例生成指导；不能把本次四张验证/外部图加入训练后继续称其为独立测试。
HU 线索可以引导训练期边界约束的设计，但尚未实现或验证此约束，不假定它会成功。
后续模型结构改变、蒸馏或数据范围调整仍需单独实验与资源核算。
