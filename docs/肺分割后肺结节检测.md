# 肺分割完成后，再检测肺结节

2026-10-23，统一网页新增流程：**加载完整CT → 完成肺分割 → 点击“肺结节检测” → 查看候选切片与列表**。

## 网页怎么用

1. 使用原来的`python/ct_workspace_web.py`入口，按已有主机配置连接板端服务。修改本次Python和HTML后，需要重启网页后端，再刷新页面。
2. 加载完整CT序列，不填写“读取层号”截取片段；进入“智能分割与三维”，执行“计算整例并重建”。
3. 所有输入层的分割完成后，上方“肺结节检测”按钮才启用。只计算一张切片、仍有未计算层、输入本身是截取片段时不会启用。
4. 点击按钮，检测直接使用内存里的原HU、几何信息和**人体约束后的预测肺掩膜body**。不重新读取原CT，不运行U-Net，也不读取专家标注作为检测输入。
5. 完成后显示候选数、估计直径、模型分数和切片矩形。点击候选可查看对应切片，也可拖动候选区的切片滑块。

本次只是候选显示，尚未增加结节精确轮廓、自动ROI裁剪或三维候选联动。矩形是中心/大小估计得到的范围，分数不是恶性概率。

## 执行位置与耗时

- 肺分割仍使用原来的实际FPGA接口、模型和比特流。
- 当前结节检测为**电脑FP32**，有可用CUDA时使用电脑GPU，否则使用电脑CPU；运行位置会显示在结果旁。没有结节FPGA调用、INT8或新bit，不能计为PL加速。
- 此按钮没有重新执行肺分割。肺分割完成所花的时间，不能再次算入结节检测耗时。
- 页面分别显示后台就绪耗时和其中的检测耗时。后台包含首次环境/模型初始化、校验、搜索和检测；检测阶段包含采样、CNN、解码、合并及跨层评分；不含此前完成的肺分割，也不是点击至浏览器显示的总时间。
- 跳过重复肺分割不等于解决了全部CPU瓶颈。搜索、采样和解码的后续优化尚未实施，不能承诺整例已降到几秒。

## 数据来源和任务状态

- 不把专家肺标注当作预测掩膜，也不使用LUNA16排除标注过滤未知病例的候选；没有结节参考标注时只显示“候选”，不显示虚构的检出率或误报数。
- 当前网页的FPGA/量化肺掩膜与开发评价使用的原FP32掩膜可能不同。原留出结果88.0%、4.89误报/CT不能直接当作这条组合链路的新验收成绩。
- 检测时锁定当前输入，其他计算或换病例请求被拒绝；停止操作在批次边界生效，不复位板卡。
- 换病例或重新分割当前病例时，之前的候选立即失效。读取候选结果必须同时匹配病例ID和结果ID。
- 同一未变化分割结果的重复请求复用已有候选，不重复执行网络。
- 新候选JSON保存在该网页病例结果目录的`<结果ID>_nodule.json`，记录CT/掩膜哈希、模型、阈值、原分割逐层回执和几何。

`POST /api/nodule/run`需要同源UI令牌和`{"case_id":"当前病例ID","backend":"PC_CNN_FP32"}`。
`GET /api/nodule/result?case=<病例ID>&result=<结果ID>`返回候选JSON；取消使用`POST /api/nodule/cancel`。
候选中心是原输入的`center_index_zyx`与LPS毫米坐标；`bbox_zyx`是`[z0,z1,y0,y1,x0,x1]`，上界不含端点。
