# 肺结节像素重叠与连续供数加速（2026-10-24）

## 目标和对照口径

本次改动针对肺结节候选检测的现有 INT8 整数图，不修改模型、权重、量化参数、采样值、候选解码、阈值或跨层规则。仍复用同一个 PYNQ-Z2、100 MHz、64 路乘加器。

上一轮用户板端输出：优化后 ARM 完整平面约 858.312 ms，预取 PL 约 610.134 ms；网络调用约 458.313 / 246.048 ms，PL 活动约 187.550 ms。此处仅记录用户控制台结果，尚未收到该轮完整回传文件并独立核验。

新的板端脚本重新测量同一输入、同一前后处理下的三路结果：`native_ARM`、`prefetch_PL`、`overlap_PL`。PL 前后对照只更换 bit/HWH，前后处理代码相同。网络调用包含同步、配置、保护检查和输出回读；硬件计数是网络调用的一部分，不能与之相加。完整平面时间包含每轮在线采样、打包、网络、解码和本平面候选合并；不包含前置肺分割、bit 加载、编译初始化或跨 Z 的整病例汇总。

## RTL 实现

### 两组结果缓冲

`lung_mac_tile8.v` 仍只有原来的 8×8 乘加阵列及一个共享量化流水线。一个像素最后一拍乘加完成后，先把部分和送入原有逐级加法树。加法树读取旧累加器后，就允许下一像素开始乘加；上一像素继续量化及输出。

两个结果槽各自保存累加结果、溢出和包标志错误、偏置、乘数、移位、零点、输出通道掩码及 ReLU 配置。槽位从第一拍输入一直占用到该像素最后一拍输出被接收。下游停顿时停止接收新像素，不允许覆盖结果。

`lung_mac_tile8_reuse.v` 在输入 LAST 接收后重新开始下一像素的权重索引；已接收但未输出的组使用计数器管理。权重重载必须等所有旧组输出完成。包装层包长度错误使用独立队列保存，不能用一个可被下一像素改变的全局错误位。

`lung_conv8_window.v` 增加输出元数据队列，按组保存坐标、帧末和输入错误。输出采用队首对应的坐标，而不是最近输入像素的坐标。原有 64 项窗口预取队列保留。

### 缓存命中连续供数

`lung_feature_cache.v` 在当前命中响应或保持响应被接收的同一拍，可以接收下一读请求并启动同步 BRAM 读取。未命中、DDR 补行、失败填充作废、边界裁剪等策略保留。

`lung_feature_window.v` 在当前窗口字被接收时，按原来的通道、核列、核行、像素顺序计算下一地址。下一字在边界内且缓存接受请求时，直接等待它的响应；边界外仍输出输入零点。停顿时保持原有数据及坐标，不提前推进。最多只有一个未消费的读响应，没有增加投机 DDR 访问。

## 验证与状态

- 128×128 真实输入，15 条命令、11 个节点：组合版本通过原始逐节点整数金标准，周期由 1,213,905 降至 924,902，约减少 23.81%。这是指定 AXI 停顿模型下的仿真周期，不是上板时间。
- 仅像素重叠版本的小图总周期约减少 3.86%，说明持续供数是必要的配套优化。
- 最终静态写入版本的 448×448 真实画布全部 11 个节点通过，15 条命令的总周期从 14,789,990 降至 11,245,672，减少约 23.96%，仿真周期加速约 1.315 倍。纯像素重叠对照为 14,221,613 周期，组合方案的主要额外收益来自连续供数。这里只比较同一 AXI 停顿模型下的 RTL 周期。
- 独立协议回归包括 147 帧缓存、共享 DDR 和 AXI-Lite 测试，以及 8,700 组原始 MAC / 权重复用整数参考向量。
- 定向并发测试覆盖坏 FIRST 与正常组相邻、三个待完成输入组、两个结果槽占满、输出稳定、等待重载及复位。
- 独立乘加核完成真实综合后的功能网表回放，端口级结果及错误隔离测试通过；这不是带布线延迟的时序仿真。整机卷积 IP 综合为 0 错误、0 严重警告。
- 完整 448×448 画布仿真、最终布线时序和资源数据以实验目录 `verification.json`、`timing_routed.rpt`、`utilization_routed.rpt` 为准。交付包只在相应检查全部通过后生成。

实际交付的源位于 `data/nodule_overlap_final_20261024_v1/rtl/`，交付副本统一放到 `data/nodule_overlap_release_20261024/nodule_overlap/`；旧的预取版本和前后处理加速版本保持原样。纯像素重叠对照位于 `data/nodule_overlap_20261024_v3/`。早期声明顺序、词法编译失败及动态索引导致多驱动的实验目录不属于交付版本。最终结果槽按生成通道和槽号使用静态地址写入，避免工具把多个生成块识别成同一内存的多写端口。

首轮布线在 100 MHz 下出现约 -1 ns 的 setup 违例，因此没有生成 bit。随后保持 RTL、时钟和 XDC 不变，进行后布线物理优化及重新布线，最终 setup/hold 和 DRC 均通过，并从当前优化后的设计直接生成 bit。报告 WNS 为 0.000 ns、WHS 为 0.015 ns；setup 余量接近边界，不建议直接提高频率，后续修改 RTL 需重新实现和核验。

## 上板运行

最终交付文件夹名称为 `nodule_overlap`，仍依赖此前已上传的 `/home/xilinx/ct_test/nodule_board` 原模型包。请完整复制目录，不要只覆盖 bit 或在旧目录中混合文件。脚本会校验清单、两份 bit、原始模型和测试输入。

Windows PowerShell 上传：

```powershell
& "C:\Program Files\Git\usr\bin\scp.exe" -r "D:\pld_picture_process\data\nodule_overlap_release_20261024\nodule_overlap" xilinx@192.168.2.99:/home/xilinx/ct_test/
```

板端 Jupyter：

```python
%run /home/xilinx/ct_test/nodule_overlap/nodule_overlap_benchmark.py --runs 5 --warmup 1 --out /home/xilinx/ct_test/nodule_overlap_speed_01
```

脚本依次运行 ARM、旧预取 PL、新流水 PL；每个 bit 先完成四个真实 patch 的 11 节点物理校验，再做完整画布对照。每个正式样本都重新在线采样，不使用预计算平面缓存。比较整个输出头、未经候选合并的中心/评分/尺寸及最终候选，任意差异均报错并丢弃速度结论。`SAME` 仅说明本次输入与执行路径一致，不等于重新完成整个数据集临床评价。

使用未存在的输出目录。如已运行过 `nodule_overlap_speed_01`，请把末尾编号改为 `02`，避免混合结果。

