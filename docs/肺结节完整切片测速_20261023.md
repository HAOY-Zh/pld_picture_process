# 肺结节完整切片测速

肺分割和结节检测都可以按中央层计时，但计算单位不同。原肺分割处理一层图像并生成肺掩膜；结节检测利用中央层附近五个采样平面，将这一层肺内的全部局部块依次计算、解码和去重，生成这一层的初步候选。整病例的跨层评分需要其他层，不能算作已经完成的单层输出。

本次只新增独立测速脚本与输入，不修改已有 `nodule_board`、bit/HWH、权重、网页或算法阈值，也不重新训练。

## 输入与口径

- 来源：已使用的开发校准 CT `1.3.6.1.4.1.14519.5.2.1.6279.6001.203425588524695836343069893813`，117 张原始切片。
- 选层：按预测肺掩膜面积最大层选择，完全不依据结节专家标注或检测效果。
- 当前输入：原始第 52 张切片（从 1 开始计数），完整 512×512 视野，32 个肺内局部块，局部块仍为五平面 ×128×128。
- 此例检测平面恰好与原始切片重合。检测器一般按 1.25 mm 的 Z 间距扫描，其他例中平面不一定恰好对应原始层；元数据会记录最近原始层和物理偏差。
- 五个采样平面偏移为 −2.5、−1.25、0、1.25、2.5 mm。此 CT 原生层间距为 2.5 mm，因此需要三张原生层，通过原有插值得到五个上下文平面；不是对五张独立切片分别完成检测。
- 为减少上传量，仅保留足够的原生 HU 上下文薄层和原搜索掩膜。32 个局部块已逐一核验，采样结果与从完整 CT 取样逐像素一致。

这次输出的是这张切片的实际测量，不代表所有切片平均耗时。此层的预测肺面积最大，覆盖块较多；肺尖或肺底层可能更快。

## 怎么读输出

终端出现的 `ARM complete plane ...` 和 `PL complete plane ...` 是中央层的候选生成耗时。`SAME` 表示所有块的五通道图与 ARM 整数图一致，不能代表与 FP32 的检出率相同。

`result.json` 的 `cpu`、`pl` 下分别有以下统计：

| 字段 | 范围 |
|---|---|
| `network_ms` | 同一完整切片全部 32 块网络推理之和；PL 仍含配置、权重装载、同步和等待 |
| `input_pack_ms` | 这张切片全部块的 ARM 量化与首层重排之和 |
| `patch_ms` | 全部块从已采样 HU 到五通道检测图的耗时之和，含量化/重排及反量化 |
| `sample_ms` | 从原生 CT 上下文取出全部块的采样耗时 |
| `decode_ms` | 将全部块的检测图转为候选中心和大小的耗时 |
| `plane_merge_ms` | 合并这一层重叠局部块候选的耗时 |
| `slice_sampling_to_candidates_ms` | 一张完整中央层从采样、输入处理、网络、解码到层内候选合并的实际总耗时 |

搜索掩膜与块列表是预先生成的，计时不包含它们的构建、先前肺分割、文件加载、bit 下载、网页显示，也不包含最终的整病例跨层评分。报告会明确记录这些边界。比较肺分割时，要选取双方范围一致的指标。

一个图像块的时间不能直接叫整片时间，也不能除以五。每张切片的块数由物理尺寸、重叠和肺内搜索范围决定，不能统一固定乘某个倍数。
