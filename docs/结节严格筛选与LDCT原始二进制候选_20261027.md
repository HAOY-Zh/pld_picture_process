## LDCT：加速候选，不启用上次变慢的压缩方式

现有实板基线完整351层为183.628秒。原板端模块约373ms/张、往返约514ms/张，通信和封装仍有开销，但这个差值不全是网络纯传输。

参考 AMD 数据流/缓冲重叠指导及 PYNQ DMA 缓存一致性要求，优先减少不改变医学运算的搬运开销。本轮首先实现独立 `/v4/ldct` 原始二进制回传与持久连接：

- 输入仍是原始 INT16 HU；板端仍调用同一 `execute_ldct`、同一所有者锁和实际 PL 算法。
- 输出使用长度受限的 JSON 元信息＋原始HU字节，替代经网络发送Base64图像；没有 zlib 编解码。
- 当前适配层仍复用父执行器的本地Base64打包/解包，这部分开销尚未消除。不能称作彻底消除所有封装成本。
- 请求ID、输入/输出SHA、模型/权重/bit/HWH、时钟及完成后DMA空闲状态仍由原完整客户端检查；失败推理不重发、不自动回退CPU。
- 七阶段实际启动自检全部保留。模型、参数、bit/HWH等21项数值资产保持一致，不新增RTL或FPGA资源，不声称功耗下降。

16张真实保存输出的封装大小核验：原JSON/Base64共11,205,275B，原始二进制共8,407,851B，减少24.97%，图像字节完全一致。这里只做本机封装与体积核对，不是板端或端到端提速结果。

4项本机协议测试通过：有符号HU全范围、帧截断/过长拒绝、原完整输出验证、长连接复用、失败不重放、未配对拒绝及全部自检阶段保留。完整候选嵌套文件/清单与客户端构造核验通过。
