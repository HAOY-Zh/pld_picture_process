# 肺部提取：离线多病例入口

打开 `data/lung_case_browser_20261014/index.html`，用顶部“选择病例”切换全部六个现有验证病例。
这是同一入口中的按需浏览：只挂载当前一例的查看页面，切换时移除上一例的页面上下文。
无需 Python 服务、网络、3D Slicer 或新比特流；**浏览时不运行模型，也不支持未知个体导入**。

## 当前覆盖

S2-006 / S2-007 / S2-008 / S3-002 / S3-003 / S3-008，全部来自原来的开发验证划分。
默认打开 S3-008，默认显示原始预测。每例都保留专家、原始预测、可选保守清理后三份结果。
三个切面、全原生三维表面、误差图、窗宽窗位、指标和物理坐标沿用已经验证的查看器。

切换病例后重置为该病例的原始预测、默认窗和默认定位，以免把上一例的设置误当成新病例结果。
默认轴位选在**原始预测面积最大**的一层；此选择只用于展示，不改推理或使用专家挑层。
“模型结果”切换会同时更新三维网格、切片、Dice 和体积。
清理层属于开发实验，尚未完成独立测试；体积不是肺功能/肺活量。
仅用于工程教学与算法演示，不作为临床诊断依据。

## 打开与交互

在 Edge/Chrome 的地址栏输入：

```text
file:///D:/pld_picture_process/data/lung_case_browser_20261014/index.html
```

1. 顶部“选择病例”：切换个体；每例首次解压 CT 和网格需要等待几秒。
2. “模型结果”：原始预测 / 清理后预测（实验）。
3. “三维模式”“切片肺区”：分别控制三维和二维里的专家/模型/对比显示。
4. “切片显示”：色块、细轮廓、误差图、原 CT；色块不透明度在“更多设置／说明”中。
5. 图像较小时用顶层“全屏”或 F11；窄屏仍允许滚动，不能保证手机四图同时清楚显示。
6. “重新加载本例”：重置当前病例页面，不重新运行模型。

不要只复制 `index.html`：分享时要复制**整个 `lung_case_browser_20261014` 文件夹**，
保留 `cases/<病例>/viewer.html` 的相对目录。它们自带所需数据，不需要另附原 CT/权重。
`data/` 被 Git 忽略，不会把医学图像跟源码推送到 GitHub。

## 数据与实现

- `python/lung_case_browser.py` 复用 `lung_island_cleanup_20261014/screen` 中已冻结的原生预测，
  校验模型、数据清单、标注、预测包与源 CT 哈希，重新读取原 CT 并核对患者/SOP 顺序/网格/间距。
- 打包过程不训练、不推理、不调整清理规则，也不访问官方 Test 或 COVID 数据。
- 输出每例 HTML 的原生 HU、专家、原始/清理掩膜和全分辨率网格；不平滑、不降采样。
- `case_browser.html` 只包含小型病例清单，按用户选择挂载单个 iframe；旧 iframe 移除，
  子页面关闭时取消刷新任务并清理 Plotly 图。运行时浏览器的内存回收由浏览器管理，不能据此保证固定 RAM 上限。
- 加载状态通过 `postMessage` 通知入口，检查当前 iframe 来源和病例 ID，不访问跨源 DOM。
- `catalog.json` 记录六例形状、默认切片、指标与页面大小；`report.json` 保留所有输入/输出身份校验。
- 原先单病例页面、冻结模型、训练划分、专家标注与清理实验报告不覆盖。

这些自带数据的 HTML 文件每例约 61–81 MiB，总包约 404 MiB，只有被选中的病例才会加载。
这是面向电脑的离线展示包，不是 PYNQ-Z2 的存储/内存/推理性能证明。
之后的未知个体导入和 FPGA 推理调度仍需单独实现 Python 后端及硬件接口。
