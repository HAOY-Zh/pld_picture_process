| 原实板验收模型 | 网络调用平均耗时 | 硬件活动平均耗时 |
|---|---:|---:|
| 原始 U-Net，一张 256×256 编码输入 | 431.566 ms | 348.465 ms |

这些是短交替验收的计时，不是新公开合成包的上板成绩。结节 53.410 ms 不含 CT 在线采样、候选解码和整层合并，不能替代此前约 597 ms/完整检测平面的时间。U-Net 相较历史 552.647/492.401 ms 更快，包含新版 RTL 的优化，不能全部算作“共用 bit”的收益。

公开运行包另行生成了不含患者数据的合成输入和参考，在 CPU 上完成独立 FP64 算子参考与 C++ 整数内核 1/2 线程逐节点对照，共 172 项节点比较通过。**这些新合成输入尚未上板**；它们只用于工程自检，不代表医学精度。bit、模型和参数与已验收包逐文件保持一致，合成副本有自己的清单，未改写历史封存包。

## 接入服务的约定

```python
from lung_nodule_shared import open_shared, load_model

engine, manifest = open_shared(package_folder)
model, parameters = load_model(package_folder, 'unet_pruned')
engine.register('lung', model, parameters, 'unet')
model, parameters = load_model(package_folder, 'nodule')
engine.register('nodule', model, parameters, 'nodule')

lung_head, lung_stats = engine.predict_codes('lung', lung_codes)
# 沿用已有肺分割后处理，肺掩膜限定结节搜索范围；检测仍读取原 CT。
nodule_head, nodule_stats = engine.predict_codes('nodule', lowered_patch_codes)
```

统一服务只建立一个所有者，串行提交任务。同一时刻仅执行一个模型，每层重新加载对应配置和权重；不要让两个线程、两个 Jupyter 内核或 LDCT 服务分别直接控制 Overlay。进程内锁不能阻止其他进程访问板卡，整机负责人仍需统一管理硬件所有权。超时或未完成传输时禁止直接切换、释放 CMA 或重载 bit。

`lung_codes` 是既有预处理后的 `uint8 [1,256,256]`；`lowered_patch_codes` 是既有五张上下文经量化、stride-two lowering 后的 `uint8 [45,64,64]`，不是 HU 原图或肺掩膜。原始 U-Net 输出零点 72，剪枝版 73，结节 head 128，必须分别处理。不要将两种 U-Net 的输出视为互相等价。

公开包提供固定 patch 网络核心，尚未提供把原生整层/整病例检测调度直接接入共享所有者的完整服务接口，也没有自动完成“肺分割→检测按钮→三维候选”的网页流程。本次不宣称 LDCT 或基础处理已进入这个共享 bit。

## 硬件资源及重建

同一 bit 为 100 MHz，17,865 LUT、20,063 FF、80 DSP、31.5 BRAM tile。三模型验证工作区同时常驻约 15.13 MiB CMA；只注册实际需要的模型即可，不把这个数当作整病例内存。

`hardware/lung_nodule_shared_20261024/` 保存匹配的 17 份 RTL、PS 配置、约束和构建入口。使用交付 bit 不需要先安装或运行 Vivado。若需重建，Vivado 2022.2 环境中从仓库根目录执行：

```text
vivado -mode batch -source hardware/lung_nodule_shared_20261024/build.tcl -tclargs data/rebuild_shared_cnn build
```

必须使用新输出目录。初次路由若未过时序，构建脚本不生成 bit；可以在保留失败报告的前提下运行同目录 `resume_physopt.tcl`，参数为相同输出目录，目标仍为 100 MHz。便携 Tcl 只改了路径，本次没有重新跑实现。新重建的 bit 必须重新核验时序、清单与实板结果，不能冒用旧 bit 哈希或验收记录。
