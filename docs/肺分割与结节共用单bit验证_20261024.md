# 肺分割与肺结节检测共用一个 bit：验证与交付

## 本轮实际做什么

复用已经完成物理板验收的 100 MHz 卷积/张量双引擎 bit，只增加统一的 Python 所有者和模型调度，不修改 Verilog、网络结构、权重、量化参数或阈值。一个 bit 的含义是：一次装载硬件，随后切换模型的权重和命令，不重新配置 FPGA。

这一包覆盖原始 U-Net、`fisher_moderate` 剪枝 U-Net、现有 2.5D 肺结节 CNN。两种 U-Net 都保留，明确选择；本轮不改网页默认模型。基础处理和 LDCT 尚未因此自动进入同一个 bit，这仍是后续整机集成工作。

| 模型 | 节点 | 每次命令数 | 验收输入 | 完整模型常驻 CMA |
|---|---:|---:|---|---:|
| 原始 U-Net | 21 | 51 | 1×256×256 INT8 编码 | 7,834,368 B |
| 剪枝 U-Net | 21 | 44 | 1×256×256 INT8 编码 | 7,506,688 B |
| 肺结节 CNN | 11 | 15 | 五张 128×128 HU patch 经原有处理成为 45×64×64 编码 | 519,680 B |

为了核验切换后的内存隔离，本包让三套模型的工作区同时常驻，共约 **15.13 MiB**。只执行一个模型时其他工作区不参与计算。这里没有另外注册整幅 448 画布，因此不把该内存数称作整病例全部内存占用。

共用的是同一套 64 路乘加阵列、量化流水线、卷积缓存、池化和拼接电路。整机 PL 资源仍为 **17,865 LUT、20,063 FF、80 DSP、31.5 BRAM tile**，不会把两份 bit 的资源表相加。只改变 Python 和 DDR 内容，不重新综合新 bit。

## 怎么保证不损失结果

验收目标是与每个模型各自冻结的 INT8 参考逐值一致，不允许仅用“看起来差不多”代替。

1. **核验模型和参数身份。** 从已验收的独立包复制模型、权重、输入、参考数据，并核对原始清单。两种 U-Net 的输出零点分别为 72、73，结节 head 为 128，分别保留，禁止切换时共用错误的零点。
2. **本机独立整数参考。** 原生 C++ 完整运行两种 U-Net 的 256×256 输入，每个模型 21 个节点与旧参考一致；结节四个真实 patch 的 11 个节点也核对。小尺寸 U-Net 另用独立稠密整数卷积/张量参考逐节点核对，为 RTL 测试生成 gold。
3. **真实 RTL 混合模型仿真。** 在同一对 RTL 引擎上顺序执行原始 U-Net→结节→剪枝 U-Net→结节→原始 U-Net，中途不复位。检查每个节点的设备输出、共享 DDR 读写边界、未完成状态清空、最终写响应及旧结果不被覆盖。U-Net 仿真使用真实权重与完整 21 节点拓扑，但输入缩至 32×32；结节用真实 128×128 patch。此项不冒充完整 256×256 U-Net 的 RTL 验证。
4. **板端完整尺寸交替验证。** 一次加载 bit，注册三模型，先取得独立运行基线，再交替运行。U-Net 用完整 256×256，结节轮换四个真实 patch。每次完成后从设备读取全部节点，逐值对照冻结参考；检查上次运行的其他模型所有设备缓冲未变化。最后再次执行 U-Net，确认结节推理没有留下错误权重、零点或缓存状态。

对 U-Net 同时保存 head 编码及 `head > 本模型零点` 的阈值掩膜用于诊断比较；它不替代网页完整 HU 预处理、回采样和三维后处理验收。结节保持检测 head 和参数，未在本包里重新评价整病例跨层候选。

如果所有节点整数值都与旧参考一致，则对相同后处理，集成没有引入额外的模型精度损失。本轮不重新训练或调参，也不是重新测数据集 Dice、检出率或误报率。三维、网页和同一病例“分割掩膜→检测范围”的端到端联调在该核心验收之后进行，不把不同测试输入的交替验证当作临床全流程成功。

## 单一硬件所有者

`lung_nodule_shared.py` 的 `SharedCNN` 是唯一入口：

- 仅 `open_shared()` 下载一次 bit；选择模型不调用 Overlay。
- 各模型保留自己的权重包、量化配置和 DDR 工作区。
- 沿用旧调度器：每一层重新配置，每一卷积块都加载该模型的权重，没有跨模型错误复用权重的捷径。
- 同一时刻只接受一个任务，重复请求立即拒绝，由上层排队，禁止两个网页请求同时写硬件寄存器。
- 检查不同模型的物理内存范围不重叠。
- 未完成或超时的 DMA 状态禁止切换、释放缓冲和重载 bit；保留内存并交由板端所有者恢复。

进程内互斥不能阻止另一个 Jupyter 内核或其他服务直接控制板卡。验收前请正常停止使用同一 FPGA 的其他服务；不要与旧测速脚本并行运行。

## 后续网页接入接口

网页服务启动时创建一个 `open_shared()` 所有者，注册需要的模型。每个任务经同一个调度入口执行；不要分别创建两个 Overlay 或把驱动交给不同线程直接调用。

```python
from lung_nodule_shared import open_shared, load_model
engine, manifest = open_shared(package_folder)
model, parameters = load_model(package_folder, "unet_pruned")
engine.register("lung", model, parameters, "unet")
model, parameters = load_model(package_folder, "nodule")
engine.register("nodule", model, parameters, "nodule")

lung_head, lung_stats = engine.predict_codes("lung", lung_input_codes)
# lung_head 是独立的 CPU 结果副本；设备工作区也有独立保护。
# 继续沿用既有肺分割后处理、肺部范围选择和结节采样/编码。
nodule_head, nodule_stats = engine.predict_codes("nodule", nodule_patch_codes)
```

示例中的输入必须来自各自现有预处理。`nodule_patch_codes` 不是直接传原始 CT，也不是把肺分割的 head 当作 CT 图像；肺掩膜用于限定检测范围，检测模型仍看原 CT 上下文。此示例是核心接口说明，没有在本轮修改网页。
