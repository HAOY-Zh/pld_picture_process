## 2. 最终运行方式

正式集成采用“一块PYNQ-Z2、一个统一板端服务、多个bit按阶段运行”。整卷HU、跨层连通域、候选排序、MPR和三维留在电脑，板端处理切片/小块及所需核心算子。

- 同一阶段批量执行，避免每张切片反复加载增强、分割、候选三个bit。
- 已有分割加速包和模型先保持冻结，按已验证版本接入。剪枝实验与默认模型分开标注。
- 全部IP同bit集成另作实验，不能作为新增模块交付前提，也不能从独立资源报告之和推导已经装得下。
- 统一服务独占硬件，负责bit、FCLK、CMA缓冲和串行调度；模块处理类使用服务提供的资源并上报状态。
- 具体资源与内存核对见 [PYNQ-Z2多模块运行评估与验收分工](PYNQ-Z2多模块运行评估与验收分工.md)。

## 3. A：你负责肺结节候选提取

### 3.1 数据与算法

本轮目标为“候选提取”，不增加第三个大网络，也不包含良恶性诊断。先做可评价的最小图像处理路线：

~~~text
原始HU + 已预测肺掩膜 + 空间信息 + 可选ROI
  → 搜索范围限定
  → 经开发实验确定的多阈值/局部结构初筛
  → 必要形态学操作
  → 跨层连通域、尺寸/形状筛选、重复合并
  → 候选中心、包围盒、粗区域、体素数和排序分数
~~~

你负责MHD/RAW读取或转换，核对HU、spacing、origin、direction与世界坐标；向B提供可接入现有CT数据结构的适配函数。验证现有肺掩膜是否漏掉高密度、贴壁等参考结节，记录由搜索范围造成的漏检。

只在开发病例上选择阈值、核与筛选规则。小目标可能被开运算删除，核大小需考虑毫米尺度；血管也可能形成候选，跨层过滤的误报/漏检变化必须实测。

先跑软件参考，判断哪些算子值得硬件化，再交C固定规则与向量。完整三维连通域和形状排序先在电脑完成，不要求C立即搬进PL。

### 3.2 交给C的内容

- 小型边界向量和真实切片HU、肺掩膜、ROI及参数。
- 预期初筛掩膜和计数；核、边界、舍入、阈值端点及形状语义。
- 哪些算子是最小必需，哪些仅是可选实验。
- 固定版本的软件参考和运行说明。

### 3.3 交给B的内容

提供可调用候选函数/模块及调用示例，不只交Notebook截图。输入为已有HU、肺掩膜、空间信息和参数；输出至少包含：

- 候选ID、世界坐标中心、数组索引与包围盒，坐标和单位明确。
- 可叠加的候选区域或局部掩膜，以及实际处理的层范围。
- 体素数、粗区域体积、HU统计、排序分数及分数含义。
- 输入/掩膜/算法/参数身份、阶段耗时和结果状态。

软件参考和硬件初筛应通过同一模块约定衔接；你处理候选算法、空间坐标及筛选错误，C处理硬件适配，B负责公共服务和显示，不替你重新实现候选算法。

### 3.4 效果验收

先下载一个官方子包做少量读取/定位自检，再预先固定开发和留出病例清单。可先以约10例开发、20例留出为小规模目标，数量由实际可用数据决定；保留阳性与参考标准下无结节的扫描。

报告每例检出参考结节数、漏检和误报候选数，查看分数阈值变化后的敏感度/每扫描误报数。保存搜索范围、初筛、跨层过滤各阶段召回损失。优先按官方匹配/排除规则评价；暂未执行官方脚本时明确自用规则，不能称为官方FROC/CPM。

数据子集结果不写成完整LUNA16基准；不直接使用官方预生成候选列表冒充自己的算法输出。

## 4. B：LDCT负责人负责增强收尾与整机

### 4.1 收尾LDCT

按 [LDCT模块接入与100MHz优化交接要求](LDCT模块接入与100MHz优化交接要求.md)，交付可连续调用的HU→HU模块、匹配版本、实际输出、效果与计时证据。

稳定50MHz版先接入；100MHz需重新实现、检查时序和实板输出，作为限时性能优化，不阻塞已验证版本。更换写入ROM的模型时同步重建bit，模型、参考和硬件身份一致。

增强前后候选检出率比较为额外实验，候选首版先跑原始CT，不让两个新模块相互等待。没有对应标签时不声称增强提高了肺分割或病灶检出质量。

### 4.2 接手现有平台

A将现有网页、分割/基础包入口、启动步骤、已知问题及验证记录交给B；B在同一套代码和发布目录中接手维护。现有MPR和三维已实现，直接复用，不重新开发。

B负责：

1. 统一CT/HU、肺掩膜、空间信息与结果身份，接入A的候选模块和C的硬件适配器。
2. 集成基础处理、LDCT、分割、ROI/候选入口，提供候选列表、点击后MPR定位及三维标记。
3. 完善体积显示：单层面积、局部片段体积和完整输入范围体积分别标注。现有代码有体积计算与条件文字显示，但集成工作台没有独立卡片，不能据此认定展示已完成。
4. 统一管理硬件锁、bit、FCLK、CMA缓冲、输入缓存、请求串行和故障状态。确认真实空闲后才切换，错误不自动复位重试或返回CPU结果伪装成功。
5. 分阶段批量调度并显示进度、已计算范围、层间取消；未计算层保持未知。滑动MPR不触发新推理。

### 4.3 整机验收与发布

集成者同时负责验收：基础快速包回传核对、模块切换、时钟、DMA、内存/CMA、持续运行、冷/热状态和端到端测速均由B统一执行与记录。

从重启板卡/启动服务到网页显示完整复现；新增一个模块，就回归已有可用模块。汇总各负责人提供的资源、时序、版本和自检，制作整机验收矩阵、原始回执及性能图表。

B修公共服务、通信、页面、发布和LDCT；A修候选算法；C修新增硬件/驱动。B不替所有人重新做算法研究或模块内部验证。

## 5. C：第三人负责共用FPGA通路

先根据A给出的参考，核对现有基础bit可复用的算子，完成最小版本：

~~~text
输入：HU + 肺掩膜 + ROI + 参数
PL：搜索区限制、HU比较、所需局部/形态学操作、像素计数
输出：初筛掩膜 + 计数 + 实际范围 + 耗时
~~~

同一通路用于候选初筛和手动ROI/HU交互定量，避免重复做两套相似硬件。先做ROI/掩膜/HU与计数，局部响应算子只增加被A软件实验确认有价值的部分。

- 与A确定算法规则，与B确定输入打包、借用资源、返回协议和版本清单。
- 现有仅HU输入协议不能假定已支持额外肺掩膜，需明确尺寸、边界和缓存同步。
- 交付可调用适配器、匹配bit/HWH、资源/时序报告、独立参考、实际输出数组和逐次计时。
- 覆盖空ROI、全图ROI、阈值端点、全空/全满掩膜、边缘尺寸与背压；掩膜逐像素一致，计数准确。
- 处理类不另开全局服务，不自行重载bit或更改全局时钟；异常保留可能的DMA访问状态，统一恢复由B管理。
- 不承担候选跨层算法、三维页面或整机验收。ROI/计数硬件是新增工作，不能把尚未实现的接口当作已交付。

配准已有代码和验证记录保留。如果已有实板结果，可作为独立附加演示；未完成的部分先列阶段，不让配准阻塞候选/ROI通路，也不为同次CT重建强行增加逐层配准。是否继续投入，待核心链路稳定后按剩余工期决定。
